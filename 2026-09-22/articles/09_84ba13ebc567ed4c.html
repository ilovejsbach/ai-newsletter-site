RiskChainBench, 위장 메시지와 위험 웹사이트를 함께 검증한다

플랫폼 악용 조직은 이모지, 동음어, 글자 쪼개기, 불필요한 기호로 안내 문구를 숨긴다. 사용자는 이렇게 위장한 링크를 따라가며 음란물, 사기, 도박, 불법 거래와 연관된 서비스로 넘어갈 수 있다. RiskChainBench는 이런 흐름을 끊기 위해, 메시지 복원과 웹 조사 성능을 한 세트로 재도록 설계됐다.

핵심 브리핑

이 벤치마크는 숨겨진 안내 문구를 AI가 원래 의미로 복원하고, 이어서 연결된 웹사이트를 조사해 위험 보고서를 쓰는 작업을 평가한다. 보안팀이 실제로 겪는 문제는 문장 해독만이 아니라, 그 결과를 바탕으로 올바른 사이트를 찾고 증거를 남기는 일이다.

연구팀은 600개 원본 세션에서 3,600개의 합성 복원 입력을 만들었다. 여기에 사람이 라벨을 붙인 600개의 로컬 웹 환경을 짝지었다. 모델은 먼저 메시지와 의도, 목적지를 복원한 뒤 같은 모델이 이어서 VLM 기반 웹 에이전트로 동작한다. 이 단계에서는 맞게 연결된 웹사이트를 조사하며, 보고서는 근거를 인용한 고정 형식으로 작성했다. 웹 조사 단계에서는 메시지 쪽 의미 정보와 도메인 평판 단서를 주지 않았다.

  • Entry Top-1은 모델별로 35.2%에서 95.2%였다
  • 웹 판단 정확도는 26.3%에서 62.8%였다
  • 복원, 전체 재구성, 웹 판단, 세부 유형 분류의 1위 모델은 서로 달랐다
  • 웹 실행 실패는 전체 웹 실행의 31.9%를 차지했다
  • 최종 판단 뒤 유형 분류 오류는 0.9%였다

연구팀은 복원 점수와 웹 조사 점수를 따로 계산했다. 그 뒤 첫 진입점 예측을 게이트로 써서 오프라인에서 합쳤다. 정답 여부는 사람 라벨로 판정했다. 증거의 충실성, 충분성, 완전성, 일관성은 고정된 멀티모달 증거 심사기가 평가했다. 연구팀은 벤치마크와 평가 절차, 초기화 가능한 로컬 샌드박스를 함께 공개했다.

방법과 결과

이 연구의 핵심은 두 작업을 분리해 재고, 실제 연결 관계는 나중에 합치는 방식이다. 먼저 메시지 복원이 맞았는지 본다. 그다음 복원한 목적지와 연결된 웹 조사 성능을 따로 본다. 이렇게 해야 앞단 오류가 뒷단 평가를 가리는 문제를 줄일 수 있다.

결과를 보면 병목은 분류보다 실행에 있었다. 웹 실행 실패가 31.9%였고, 최종 판단 뒤 세부 유형 오류는 0.9%였다. 연구팀은 안정적인 웹 탐색과 위험 판단이 핵심 병목이라고 적었다. 다만 모델별 우세 영역이 달라서, 한 모델이 모든 단계에서 가장 높지는 않았다.

업계의 움직임

아직 공개된 반응은 확인되지 않았다.

시사점과 체크포인트

금융권 보안 관제에 이 벤치마크를 바로 적용하려면, 링크 복원과 웹 조사 단계를 분리해 평가하는 체계부터 점검할 필요가 있다. 지금 운영 중인 탐지 모델이 메시지 해독에 강한지, 실제 웹 조사 자동화까지 버티는지는 다른 문제다.

우리 회사라면 다음을 먼저 확인하면 된다.

  • 피싱·불법 유도 문구 탐지 로직이 이모지, 동음어, 문자 분해를 얼마나 버티는지
  • 링크 추적 뒤 캡처, 근거 보존, 보고서 작성까지 자동화가 되는지
  • 웹 실행 실패가 많은 구간이 브라우저 제어인지, 접근 차단인지, 모델 판단인지
  • 조사 단계에서 도메인 평판 없이도 결론을 낼 수 있는지

이번 연구는 로컬 환경 기준 평가다. 실제 인터넷의 차단 정책, 로그인 장벽, 실시간 변경 요소는 반영되지 않을 수 있다. 운영 도입 전에는 외부망 접속 정책과 증거 보존 기준을 함께 맞춰야 한다.

주요 용어

벤치마크(Benchmark): 모델 성능을 같은 조건에서 비교하는 평가 틀 VLM(Vision-Language Model): 이미지와 텍스트를 함께 처리하는 모델 샌드박스(Sandbox): 외부와 분리해 안전하게 실행하는 시험 환경 증거 기반 보고서(Evidence-grounded report): 근거 자료를 명시해 결론을 적는 보고서 Top-1 정확도(Top-1 accuracy): 모델이 첫 번째로 고른 답이 정답인 비율
