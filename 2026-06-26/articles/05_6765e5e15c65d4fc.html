바이두 OCR, 긴 문서에서 메모리 고정

엔드투엔드 OCR 모델은 출력이 길어질수록 디코더 캐시가 쌓여 메모리와 속도가 함께 나빠진다. 언리미티드 OCR은 이 병목을 정확도보다 먼저 겨냥한다. 비전 인코더는 DeepSeek OCR의 DeepEncoder를 유지하고, 디코더 주의 메커니즘만 R-SWA로 바꿔 캐시 크기를 상수 수준으로 묶으려 했다. 긴 문서를 여러 페이지로 잘라 후처리하는 대신, 더 긴 단일 패스를 현실화하려는 접근이다.

원문이 말하는 핵심

언리미티드 OCR은 3B 파라미터 MoE 모델이며, 추론 시 활성화 파라미터는 500M이다. DeepSeek OCR을 기반으로 이어 학습했고, 디코더의 표준 멀티헤드 어텐션(MHA)을 참조 슬라이딩 윈도우 어텐션(R-SWA)으로 대체했다.

주요 포인트는 다음과 같다.

  • 긴 출력에서도 KV 캐시 크기를 상수에 가깝게 유지
  • 32K 최대 길이 안에서 수십 페이지를 한 번에 파싱
  • OmniDocBench v1.5에서 93.23 기록
  • DeepSeek OCR 대비 6.22포인트 상회

무엇이 달라졌나

표준 어텐션은 생성된 모든 토큰의 key/value를 계속 저장하므로, 출력 길이 T가 늘수록 캐시도 함께 커진다. 언리미티드 OCR의 R-SWA는 이 연결을 끊는다.

새 토큰은 두 부류만 본다.

  • 모든 참조 토큰(reference tokens): 시각 토큰과 프롬프트
  • 직전 n개 출력 토큰: 기본값 128

이보다 오래된 출력 토큰은 제거된다. 그래서 캐시는 `m + n` 크기의 고정 큐가 되고, T가 커져도 메모리와 단계별 지연이 평평하게 유지된다는 설명이다.

비전 인코더와 학습 방식

인코더는 DeepEncoder를 그대로 이어받는다. SAM-ViT의 윈도우 어텐션과 CLIP-ViT의 글로벌 어텐션을 계단식으로 쓰고, 중간 다리에서 16배 토큰 압축을 적용한다.

  • 1024×1024 PDF 이미지 → 256개 시각 토큰

즉 긴 문서 처리에서 디코더뿐 아니라 프리필(prefill) 부담도 줄이는 구조다.

해상도 모드는 원래 다섯 가지를 지원하지만, 이 모델은 둘만 유지한다.

  • Base: 1024×1024, 다중 페이지용
  • Gundam: 단일 페이지용 동적 해상도

학습은 처음부터가 아니라 DeepSeek OCR 체크포인트에서 4,000스텝 이어 학습했다. DeepEncoder는 고정하고 디코더만 학습했으며, 8×16 A800 GPU와 약 200만 문서 샘플을 사용했다고 적었다.

벤치마크와 속도는 어떻게 읽어야 하나

OmniDocBench v1.5에서 전체 점수 93.23, v1.6에서 93.92를 기록했다. 본문은 text, formula, table 인식 전반에서 향상이 유지된다고 설명한다.

속도도 함께 개선됐다고 한다.

  • Base 모드 TPS: 5,580
  • DeepSeek OCR TPS: 4,951
  • 향상 폭: 12.7%

긴 출력에서는 차이가 더 커진다. 출력 상한 6,000토큰에서 DeepSeek OCR이 35% 느리다고 제시됐다.

즉 이 모델의 성능 포인트는 단순 점수보다, 출력 길이가 커질수록 비용 증가가 덜하다는 데 있다.

실무에서는 어디에 쓰일까

페이지별 분할이 번거로운 문서 처리에 맞는다. 대표 사례로는 책 단위 전사, 텍스트·표·수식·읽기 순서를 한 번에 뽑는 문서 파싱 파이프라인, 폴더 단위 병렬 배치 처리 등이 제시됐다.

실행 경로도 둘로 나뉜다.

  • Transformers: `trust_remote_code=True`, CUDA GPU 필요
  • SGLang: 운영용 처리량을 위한 OpenAI 호환 API

단일 이미지는 Gundam 모드, 다중 페이지 PDF는 `infer_multi`와 Base 모드를 사용한다. 설정 예시로 `max_length=32768`, `ngram_window=128`, `no_repeat_ngram_size=35`가 제시됐다.

아직 조심할 점

이름과 달리 진짜 무제한은 아니다. 32K 컨텍스트 한도가 남아 있고, 페이지 수가 늘수록 프리필은 여전히 커진다.

또한 다중 페이지는 Base 모드만 사용하므로, 아주 작은 글자는 놓칠 수 있다. R-SWA를 ASR이나 번역에 확장할 수 있다는 언급도 있지만, 이는 아직 출하된 결과가 아니라 향후 가능성 수준이다.

결국 강점은 '긴 출력에서 디코더 비용 억제'이지, 모든 긴 문서 문제를 자동으로 해결하는 것은 아니다.

출처와 한계

성능 수치는 논문·벤더 측 비교에 기반한다. DeepSeek OCR과 같은 계열 비교에는 유리하지만, 다른 장문 문서 파서나 상용 OCR API와의 범용 비교는 이 발췌만으로 충분하지 않다.
