netdata/netdata

서버를 초 단위로 감시하는 Netdata, 최신판 배포 중단

★ 80,838이번 주 +104GoGPL-3.0 법무 확인릴리스 v2.12.0 (09.30)최근 활동 10.08테스트 있음예제 없음AGENTS.md 없음

netdata/netdata는 Go로 만든 모니터링 도구로, 저장소는 2013년 6월에 만들어졌다. 만든 쪽은 클라우드 네이티브 컴퓨팅 재단(CNCF)의 회원이라고 밝혔다. v2.12.0 릴리스 노트는 OpenTelemetry 추적(초기 접근), Redfish 기반 서버 하드웨어 대역 외 감시, SNMP 토폴로지 진단, S3 객체 스토리지 수집기를 새 기능으로 꼽는다. 그러나 이 버전은 시작할 때 멈추는 문제로 설치 파일이 내려갔다.

무엇을 하는 물건인가

netdata/netdata는 서버와 인프라의 상태 수치를 초 단위로 모아 화면과 알림으로 보여 주는 모니터링 도구다. 서버실에 계기판을 달아 두고 이상 징후가 생기면 경보가 울리게 하는 일에 가깝다. 이 도구가 없으면 수집 프로그램을 따로 깔고 대시보드를 하나씩 직접 만들어야 한다.

스펙과 도입 조건

  • 언어: Go로 작성했다.
  • 설치 형태: 설치 프로그램으로 설치하며, 텔레메트리telemetry — 제품 개선을 위해 사용 통계를 만든 쪽에 자동 전송하는 데이터를 끄는 옵션이 있다. 저장소에 Dockerfile이 있고, 릴리스 노트에는 Windows용 Hyper-V와 RDP 수집 항목도 나온다.
  • 구성 요소: Agent는 오픈소스 핵심으로 수집, 저장, 머신러닝, 알림, API를 맡는다. UI는 비공개 소스이며 Agent나 Cloud와 쓰면 무료이고 CDN으로 전달한다. Cloud는 비공개 소스이고 무료와 유료 구간이 있으며 원격 접속, SSO, 확장을 더한다.
  • 의존 서비스: Netdata Cloud는 선택이며, 없이도 동작한다고 한다.
  • 라이선스: Agent는 GPLv3 이상이다.
  • 성숙도: 최신 릴리스는 v2.12.0(2026년 9월 30일)이다. 의존하는 도구의 상위 버그로 시작할 때 무작위로 멈추는 문제가 발견돼 설치 파일이 릴리스 페이지에서 내려졌다. 만든 쪽은 v2.12.1에서 고칠 것으로 예상하며, 그 전에는 v2.11.1을 쓰라고 안내한다.

이럴 때 쓰면 좋다

  • 야간 배치 서버의 CPU와 디스크 입출력을 초 단위로 남겨 두었다가 지연이 생긴 시각을 확대해 원인 구간을 짚을 때 쓴다.
  • 운영 서버 여러 대의 지표metric — CPU 사용률처럼 시간에 따라 기록되는 상태 수치를 상위 서버로 모아 보고, 이상 탐지anomaly detection — 평소 패턴에서 벗어난 값을 머신러닝으로 골라내는 기능 점수로 평소와 다른 서버를 먼저 살필 때 쓴다.
  • 기존 Nagios나 Zabbix 모니터링은 그대로 두고 초 단위 지표와 자동 대시보드를 덧붙이는 시범 도입에 쓴다.

핵심 기능

  • 자동 구성: 별도 설정 없이 대시보드를 자동으로 만들고, 머신러닝 이상 탐지, 알림, 상관 분석을 내장한다.
  • 계층 보관: 지표를 초, 분, 시간 단위 3단계로 보관하고 화면 확대 수준에 맞춰 자동으로 조회한다. 보존 기간은 디스크 용량이 허락하는 만큼이다.
  • 확장 구조: 에이전트를 여러 대 두는 수평 확장, 상위 서버(Parent)를 키우는 수직 확장, Netdata Cloud로 여러 인프라를 한 화면에서 보는 방식을 지원한다.

성능과 운영 비용

Netdata는 서버 지표를 초 단위로 모으고 대시보드와 이상 탐지를 자동으로 만들어 준다. 에이전트를 서버마다 설치하고, 지표를 상위 서버(Parent)로 모아 볼 수도 있다. Netdata Cloud는 선택 사항이며, 쓰지 않아도 동작한다.

만든 쪽은 운영 서버 기본 설정에서 CPU 약 5%와 메모리 150MiB를 쓴다고 밝혔다. 머신러닝과 알림을 끄고 임시 저장소를 쓰면 CPU 1% 미만, 메모리 약 100MiB로 줄어든다. 상위 서버는 적절한 하드웨어가 있으면 초당 수백만 개 지표까지 처리한다고 한다. 필요한 하드웨어 사양은 적혀 있지 않다.

디스크 쓰기는 지표를 17분마다 기록하되 시점을 고르게 분산하고, 압축(ZSTD)과 직접 입출력을 쓴다. 메모리 전용 모드(alloc 또는 ram)로 돌리면 디스크에 쓰지 않는다.

만든 쪽은 Prometheus와 Grafana 조합보다 효율적이고 배포가 쉽다고 주장하며 성능 비교 문서 링크를 달아 두었다. 비교 수치는 여기에 적혀 있지 않다. 상용 SaaS와 달리 모든 지표를 샘플링과 집계 없이 자기 인프라에 저장하고, 규모를 키워도 비용이 치솟지 않는다고 한다.

사내 도입 체크

  • 외부 연결: Cloud는 선택이지만 원격 접속, SSO, 중앙 알림 설정은 Cloud 기능이라 쓰면 외부 서비스를 거친다. UI는 CDN으로 전달한다고 적혀 있어 폐쇄망에서 화면이 그대로 동작하는지는 확인 필요.
  • 데이터 반출: 익명 텔레메트리를 수집하며 설치 옵션이나 파일 생성으로 끌 수 있다. 만든 쪽은 개인 데이터는 수집하지 않고 지표는 사용자 인프라에 저장한다고 밝혔다. Cloud 연결 시 지표가 올라가는 범위는 확인 필요.
  • 유지보수 주체와 상용 대체: 저장소 소유자는 netdata 계정이며 유료 구간이 있는 Cloud 상품도 운영한다. 이름이 나온 상용 대체 제품은 적혀 있지 않아 확인 필요.
  • 버전 선택: v2.12.0 설치 파일은 내려갔으므로 v2.11.1을 쓰라는 안내를 따라야 한다. v2.12.1이 실제로 나왔는지는 확인 필요.
