코딩 에이전트에 절차와 기억을 붙이는 도구

★ 265,452이번 주 +6,116JavaScriptMIT 사내 사용 가능릴리스 v2.2.1 (09.08)최근 활동 09.22테스트 있음예제 있음AGENTS.md 있음

사내에서 코딩 에이전트를 쓸 때 가장 번거로운 일은 절차를 매번 다시 짜는 일이다. 어떤 팀은 계획과 테스트, 검토 단계를 프롬프트로 길게 적는다. 어떤 팀은 도구별 설치 방식이 달라서 환경을 맞추는 데 시간을 쓴다. ECC는 이런 반복을 줄이려는 쪽에 초점을 맞춘 저장소다.

무엇을 하는 물건인가

ECC는 코딩 에이전트가 일하는 순서를 미리 정해 두는 도구다. 에이전트가 코드를 쓰기 전에 계획을 세우고, 테스트로 바뀐 내용을 확인하며, 다른 맥락에서 자기 결과를 다시 검토하게 만든다. 이 도구가 없으면 같은 지시를 프롬프트마다 다시 적고, 검토와 기록도 사람이나 별도 도구가 나눠 맡아야 한다. 자주 쓰는 업무 요령을 팀 공용 체크리스트로 붙여 두는 방식에 가깝다.

스펙과 도입 조건

  • 언어는 JavaScript다.
  • 설치는 npm 패키지 ecc-universal로 진행한다.
  • 범용 설치는 Node.js 18 이상이 필요하다.
  • Claude Code 플러그인 설정에는 Git과 Claude Code 2.1 이상이 필요하다.
  • Claude Code, Codex, Kimi Code용 안내형 설치를 제공한다.
  • Claude Code는 기본 플러그인 방식과 설정 파일 방식도 지원한다.
  • Codex에는 지원되는 동기화 경로가 있다.
  • Cursor, OpenCode, Gemini, Zed, GitHub Copilot, Qwen 등에는 기능 제한이 있는 어댑터를 제공한다.
  • 라이선스는 MIT다.
  • 최신 릴리스는 v2.2.1로 표시돼 있다.

이럴 때 쓰면 좋다

  • 야간 배치 전에 코딩 에이전트가 수정안을 내면 테스트와 재검토까지 같은 절차로 돌리고 싶을 때 맞다.
  • 고객 문의 분류 규칙이나 사내 자동화 스크립트를 여러 에이전트로 시험할 때 설치 방식을 통일하고 싶다면 쓸 만하다.
  • 규정 문서 검색 보조 도구를 만들면서 자주 성공한 프롬프트와 작업 요령을 팀 자산으로 남기려는 경우에 어울린다.

핵심 기능

  • 계획, 테스트, 구현, 검토, 확인, 기억, 개선의 순서를 작업 방식에 넣는다.
  • 68개 에이전트와 292개 스킬, 94개 레거시 명령 호환 기능을 제공한다.
  • hooks, rules, memory, continuous learning, AgentShield 보안 점검을 포함한다.

왜 지금 주목받나

코딩 에이전트 활용이 늘수록 팀은 프롬프트보다 운영 절차를 더 자주 문제로 만난다. ECC는 그 절차를 한 번 설치해 반복해서 쓰게 하는 데 초점을 둔다. Claude Code에 가장 잘 맞추되 Codex와 Kimi Code까지 같은 안내형 설치 흐름으로 묶은 점도 눈에 띈다. 만든 쪽은 지원 상태가 도구마다 다르다고 밝혔고, 기능이 모두 같다고 보면 안 된다.

사내 도입 체크

  • 외부 API 키 필요 여부는 이 저장소 설명만으로는 확인되지 않는다.
  • 진단 정보는 자동 업로드하지 않는다고 적혀 있다.
  • 유지보수 주체는 개인 계정 소유 저장소로 보인다.
  • Claude Code, Codex 같은 상용 코딩 도구를 보완하는 성격이어서 대체 제품은 있다.

주요 용어

에이전트(Agent): 사용자의 지시를 받아 여러 단계를 수행하는 AI 도구 컨텍스트 윈도(Context Window): 모델이 한 번에 보고 처리하는 입력 범위 플러그인(Plugin): 기존 프로그램에 기능을 덧붙이는 추가 구성요소 후크(Hook): 특정 시점에 자동으로 실행되는 연결 규칙 어댑터(Adapter): 서로 다른 도구를 이어 주는 중간 연결부
