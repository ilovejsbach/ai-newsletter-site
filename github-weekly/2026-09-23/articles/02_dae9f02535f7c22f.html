코딩 보조에 개발 절차를 심는 스킬 묶음

★ 98,525이번 주 +3,711JavaScriptMIT 사내 사용 가능릴리스 0.6.10 (09.18)최근 활동 09.23테스트 없음예제 없음AGENTS.md 있음

사내에서 AI 코딩 보조를 써도, 누가 어떻게 쓰느냐에 따라 결과 차이가 크게 난다. 이 저장소는 그 차이를 줄이려는 쪽에 가깝다. 만든 쪽은 숙련 개발자의 절차와 점검표를 스킬 형태로 묶어 여러 도구에 배포한다고 밝혔다. 특정 모델보다 작업 순서와 검증 규칙을 통일하는 데 초점을 둔다.

무엇을 하는 물건인가

이 묶음은 코딩 보조 도구가 정해진 절차에 따라 일하게 만든다. 사람이 숙련자 점검표를 옆에 두고 단계마다 확인하듯, 이 도구는 설계·구현·시험·검토 순서를 고정해 준다. 이 도구가 없으면 사용자가 각 단계 지시를 직접 적고, 중간 점검도 매번 따로 시켜야 한다. 개별 기능만 넣을 수도 있다.

스펙과 도입 조건

  • 언어는 JavaScript로 표시돼 있다.
  • 설치 형태는 CLI 설치, 각 도구용 플러그인 설치, 로컬 복제로 제시돼 있다.
  • 외부 API 키 필요 여부는 밝혀져 있지 않다.
  • 라이선스는 MIT다.
  • 최신 릴리스는 0.6.10이며 2026년 9월 18일 기준으로 공개돼 있다.

이럴 때 쓰면 좋다

  • 사내 개발팀이 고객 상담 분류 도구를 만들 때, 요구사항 정리부터 코드 검토까지 같은 절차를 강제하고 싶을 때 쓸 만하다.
  • 야간 배치 점검 자동화를 만들 때, 구현은 빨리 하되 테스트와 실패 시 중단 규칙을 빼먹지 않게 하고 싶을 때 맞는다.
  • 여러 팀이 서로 다른 코딩 보조를 쓰는 환경에서, 리뷰 기준과 작업 순서를 공통으로 맞추고 싶을 때 유용하다.

핵심 기능

  • 개발 생애주기에 맞춘 9개의 슬래시 명령어를 제공한다.
  • 작업 내용에 따라 API 설계나 화면 구현 같은 스킬을 자동으로 켠다.
  • 25개의 스킬을 묶음으로 설치하거나 필요한 스킬만 골라 넣을 수 있다.

왜 지금 주목받나

이 저장소는 코딩 보조를 더 똑똑하게 만드는 데서 멈추지 않고, 같은 절차를 반복하게 만드는 데 초점을 둔다. /build는 계획 승인 한 번 뒤에 작업을 자율 실행하지만, 각 작업은 여전히 테스트 중심으로 진행하고 실패나 위험 단계에서 멈춘다고 적혀 있다. 사람이 단계 사이를 일일이 끼어들지 않아도 되지만 검증은 생략하지 않는 구조다. 여러 코딩 보조 도구에 같은 스킬을 붙일 수 있다는 점도 확산 속도를 높인다.

사내 도입 체크

  • 여러 코딩 보조 도구에 붙일 수 있지만, 실제 지원 범위와 사내 표준 도구 호환성은 확인이 필요하다.
  • 외부 API를 반드시 호출하는 구조인지는 확인이 필요하다.
  • 만든 쪽은 개인 계정이 아니라 addyosmani 이름으로 배포하고 있다.
  • 상용 코딩 보조 도구의 사내 가이드 기능과 일부 겹칠 수 있어, 기존 도구의 정책 기능으로 대체 가능한지 비교가 필요하다.

주요 용어

슬래시 명령어(slash command): 대화창에 /build처럼 입력해 정해진 작업을 실행하는 명령 품질 게이트(quality gate): 다음 단계로 넘기기 전 반드시 확인하는 검증 기준 플러그인(plugin): 기존 도구에 붙여 기능을 더하는 추가 구성요소 TDD(Test-Driven Development): 테스트를 먼저 만들고 그 기준에 맞춰 구현하는 개발 방식
