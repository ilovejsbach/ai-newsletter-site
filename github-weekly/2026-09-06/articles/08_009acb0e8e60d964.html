서버 없이 붙이는 벡터 검색 엔진의 새 릴리스

스타 15,796 · 이번 주 +0 · C++ · Apache-2.0 사내 사용 가능 · 최근 릴리스 v0.7.0 (08.24) · 테스트 있음 · 예제 있음 · AGENTS.md 없음

이 저장소는 벡터 검색을 별도 서버가 아닌 라이브러리 형태로 제공한다. 문서 검색, 코드 검색, 에이전트 메모리 저장처럼 애플리케이션 가까운 곳에 검색 기능을 넣는 데 초점을 맞춘다. 최근 릴리스에서는 인덱스 종류와 배포 대상, 아키텍처 지원 범위를 넓혔다. 금융IT 조직에서는 규정 문서 검색, 상담 지식 검색, 내부 코드 검색 같은 실험에 바로 연결할 수 있다.

무엇을 하는 물건인가

이 저장소는 서버를 따로 세우지 않고 애플리케이션 안에 바로 넣어 쓸 수 있는 벡터 데이터베이스다. 문서나 코드의 의미를 저장해 비슷한 내용을 빠르게 찾는다. 키워드 검색과 구조화 필터도 한 질의에 합칠 수 있다. 사내 문서함 안에 즉석 검색 서랍을 끼워 넣는 도구에 가깝다.

스펙과 도입 조건

  • 핵심 구현 언어는 C++다.
  • 공식 SDK는 Python, Node.js, Go, Rust, Dart/Flutter를 지원한다.
  • Python 패키지는 pip로 설치한다.
  • Python은 64비트 Python 3.10~3.14가 필요하다.
  • 별도 서버 없이 인프로세스(프로그램 내부 실행) 라이브러리로 동작한다.
  • 지원 플랫폼은 Linux, macOS, Windows다.
  • Linux는 x86_64와 ARM64, glibc와 musl을 지원한다.
  • macOS는 ARM64와 x86_64를 지원한다.
  • 라이선스는 Apache-2.0이다.
  • 최신 릴리스는 v0.7.0이다.

이럴 때 쓰면 좋다

  • 규정 문서 검색 시스템을 만들 때 별도 검색 서버 없이 업무 애플리케이션 안에 의미 검색을 넣고 싶을 때 맞다.
  • 고객센터 지식베이스에서 키워드 검색과 유사 답변 검색을 함께 써 문의 분류 정확도를 높일 때 유용하다.
  • 내부 코드와 배치 스크립트를 로컬에서 검색해 운영 장애 대응 속도를 높이려는 팀에 적합하다.

핵심 기능

  • 밀집 벡터와 희소 벡터를 모두 지원하고 다중 벡터 질의도 처리한다.
  • 벡터 유사도, 전문 검색, 구조화 필터를 한 번의 하이브리드 검색으로 합친다.
  • WAL로 영속성을 보장하고 여러 프로세스가 같은 컬렉션을 동시에 읽을 수 있다.

성능과 운영 비용

저장소는 수십억 개 벡터를 밀리초 단위로 검색할 수 있다고 소개하지만, 발췌에는 같은 문장에 붙은 측정 환경과 벤치마크 수치가 없다. 운영 측면에서는 서버리스가 아니라 인프로세스 구조라 별도 검색 서버와 네트워크 홉이 줄어든다. v0.7.0에서는 macOS arm64 C API 라이브러리 크기를 37 MB에서 22 MB로 줄였고 감소 폭은 40%다. 같은 릴리스에서 Linux ARM64, macOS ARM64, Alpine Linux, Windows, Android, iOS용 사전 빌드 SDK도 함께 제공해 배포 부담을 낮췄다.

사내 도입 체크

  • 외부 API 키 없이 로컬 라이브러리로 쓸 수 있다.
  • 인프로세스 구조라 문서를 외부 서비스로 보내지 않는 배치가 가능하다. 실제 데이터 반출 여부는 상위 애플리케이션 설계에 달렸다.
  • 유지보수 주체는 Alibaba 조직이다.
  • 상용 대체재는 있다. 관리형 벡터 DB나 검색 SaaS가 비슷한 기능을 제공하지만, 이 저장소는 애플리케이션 내장형이라는 점이 다르다.

주요 용어

벡터 데이터베이스(Vector Database): 문장이나 이미지의 의미를 숫자 배열로 저장하고 비슷한 항목을 찾는 저장소 RAG(Retrieval-Augmented Generation): 외부 문서를 찾아 AI 답변에 붙여 정확도를 높이는 방식 HNSW: 빠른 유사도 검색에 쓰는 그래프 기반 인덱스 WAL(Write-Ahead Logging): 장애가 나도 데이터를 복구할 수 있게 먼저 기록하는 저장 방식 Full-Text Search: 단어와 구문을 기준으로 문서를 찾는 검색 방식
