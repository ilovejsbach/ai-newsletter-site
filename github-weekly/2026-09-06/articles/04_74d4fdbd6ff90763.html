트레이딩 도구가 커지면 분석 기능보다 운영 분리가 먼저 문제가 된다. API 서버가 장시간 전략 실행까지 떠안으면 장애 범위가 커진다. QuantDinger는 v5에서 이 경계를 다시 나눴다. 사내에서 AI 서비스 운영 구조를 공부할 때 참고할 만한 사례다.

무엇을 하는 물건인가

QuantDinger는 자체 호스팅형 AI 트레이딩 운영체제다. 시장 조사, Python 전략 개발, 서버 측 백테스트, 모의·실거래, 모니터링을 한 플랫폼에 담았다. 웹, 모바일 H5, 사람용 API, Agent Gateway, MCP 접근도 지원한다. 비유하면 리서치 도구와 주문 실행기, 운영 대시보드를 한 건물 안에 넣은 서비스 틀에 가깝다.

스펙과 도입 조건

  • 언어는 Python이다.
  • 설치 형태는 최신 릴리스 기준 멀티 아키텍처 Docker 이미지다.
  • amd64와 arm64 이미지를 제공한다.
  • PostgreSQL 기반 상태 저장소와 Redis를 사용한다.
  • 웹, 모바일 H5, Human API, Agent Gateway, MCP 접근 경로를 제공한다.
  • 라이선스는 Apache-2.0이다.
  • 최신 릴리스는 v5.0.26이며, 소스 버전은 VERSION 파일에 둔다.

이럴 때 쓰면 좋다

  • 소규모 금융 서비스팀이 고객별 전략 실행 환경을 분리한 자체 호스팅형 시범 서비스를 만들 때 맞다.
  • 야간 스케줄러와 전략 실행 작업을 API 서버와 분리해 장애 범위를 줄이고 싶을 때 유용하다.
  • 모의투자부터 시작해 제한된 API 키로 실거래 전환 절차를 단계적으로 점검할 때 적합하다.

핵심 기능

  • 여러 제공자의 AI 시장 조사와 분석 기능을 제공한다.
  • Python 지표와 Strategy API V2로 전략을 개발하고 서버 측 백테스트를 수행한다.
  • 암호자산 거래소와 전통 브로커에 대해 모의·실거래 실행과 모니터링을 지원한다.

이번 릴리스에서 바뀐 점

이번 릴리스 발췌에는 v5.0.26용 Docker 이미지 태그가 실렸다. 세부 변경 목록은 비교 링크로만 연결했고, 본문에는 구체 기능이 없다. 대신 v5 계열의 큰 변화는 운영 경계 재구성에 있다. HTTP API는 장시간 트레이딩 루프와 스케줄러를 더 이상 맡지 않고, 트레이딩·스케줄링·Celery 작업·마이그레이션을 별도 프로세스로 나눈다.

사내 도입 체크

  • 실거래는 명시적으로 켜야 하며, 저장소는 먼저 모의투자를 권한다.
  • 브로커 자격 증명과 시장 데이터, 전략 코드는 운영자 통제 아래에 둔다고 적었다.
  • 외부 AI 추론 호출은 제공자 구성에 따라 발생한다.
  • 유지보수 주체는 OpenByteInc 조직 계정이다.
  • 대체 가능한 상용 제품은 있다. 이 저장소는 멀티테넌트 SaaS 운영 틀까지 함께 제공하는 점이 다르다.

주요 용어

로컬 퍼스트(Local-first): 핵심 데이터와 실행을 사용자 환경에서 우선 처리하는 설계 멀티테넌트(Multi-tenant): 한 시스템이 여러 고객이나 조직을 분리해 함께 쓰는 구조 Celery: Python 작업을 백그라운드에서 처리하는 분산 작업 도구 OpenAPI: API 규격을 문서와 검증에 함께 쓰는 형식 Prometheus: 시스템 지표를 수집하는 모니터링 도구
