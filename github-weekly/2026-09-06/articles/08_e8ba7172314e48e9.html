LLM 서빙 속도와 메모리를 아끼는 엔진

스타 91,051 · 이번 주 +0 · Python · Apache-2.0 사내 사용 가능 · 최근 릴리스 v0.28.0 (08.26) · 테스트 있음 · 예제 있음 · AGENTS.md 있음

모델을 잘 고르는 일만큼 잘 돌리는 일도 중요하다. 같은 모델이라도 서빙 엔진에 따라 처리량과 메모리 사용량이 크게 달라진다. 특히 사내 챗봇이나 문서 검색처럼 동시 요청이 몰리는 서비스는 인프라 차이가 곧 비용 차이로 이어진다. vLLM은 이런 운영 단계의 효율을 노린 프로젝트다.

무엇을 하는 물건인가

vLLM은 대규모 언어모델을 빠르게 실행하고 서비스 형태로 내놓게 해 주는 오픈소스 엔진이다. 모델 파일을 받아 API 서버로 띄우고, 여러 요청을 효율적으로 처리한다. 개발팀은 모델을 바꾸더라도 운영 방식은 비슷하게 유지할 수 있다. 콜센터를 늘리지 않고 접수 창구와 대기열 운영을 정교하게 바꾸는 일에 가깝다.

스펙과 도입 조건

  • 언어는 Python이다.
  • 설치 형태는 pip 패키지이며, uv 설치도 지원한다.
  • Docker 이미지를 제공한다.
  • OpenAI 호환 API 서버와 Anthropic Messages API, gRPC를 지원한다.
  • NVIDIA GPU, AMD GPU, Intel GPU와 x86·ARM·PowerPC CPU를 지원하며,
  • Google TPU, Intel Gaudi, IBM Spyre, Huawei Ascend, Rebellions NPU, Apple Silicon, MetaX GPU 등 하드웨어 플러그인도 지원한다.
  • 라이선스는 Apache-2.0이다.
  • 최신 릴리스는 v0.28.0이다.

이럴 때 쓰면 좋다

  • 사내 문서 검색 서비스에 붙일 자체 LLM API 서버를 구축하려는 인프라팀에 맞다.
  • 야간 배치로 대량 요약이나 분류 작업을 돌리는데 GPU 메모리 부담을 줄이고 싶을 때 쓸 수 있다.
  • 외부 모델 API 비용을 줄이기 위해 오픈소스 모델을 내부 서버에서 직접 운영하려는 금융IT 조직에 적합하다.

핵심 기능

  • PagedAttention과 연속 배칭, prefix caching으로 메모리와 처리 효율을 높인다.
  • Hugging Face의 200개 이상 모델 아키텍처를 폭넓게 지원한다.
  • 구조화 출력과 도구 호출, 추론 파서, 스트리밍 출력을 지원한다.

성능과 운영 비용

이 저장소는 처리량과 메모리 효율을 핵심 가치로 내세운다. README 첫머리에는 수치를 표로 따로 보여주지 않지만, PagedAttention과 연속 배칭 같은 방식으로 메모리와 비용을 줄이려 한다. OpenAI 호환 API 서버를 제공해 기존 앱과 붙이기 쉽다.

이번 v0.28.0 릴리스 노트에는 구체 수치와 조건이 일부 들어 있다. Kimi-K3 최적화에서는 커널 수준 속도를 1.5~3배 높였다고 적었다. 같은 묶음에서 적응형 speculative token budget으로 DSpark TTFT를 약 60% 개선했다고 밝혔다. 선택형 shared-expert sharding은 GPU당 메모리를 약 17 GiB 아낀다고 적었다. 이 수치는 프로젝트 측 릴리스 하이라이트 기준이며, 대상 모델과 커널 조건이 함께 붙어 있다.

운영 부담은 하드웨어 종류에 따라 달라진다. CUDA 13.0과 12.9, ROCm, CPU, XPU용 이미지를 따로 배포한다. 여러 GPU와 분산 추론을 염두에 둔 기능이 많아 단일 서버 실험부터 대규모 운영까지 폭이 넓다.

사내 도입 체크

  • 외부 API 키 없이 자체 모델 서빙용으로 쓸 수 있다. 다만 내려받을 모델 소스와 배포 환경 정책은 따로 검토해야 한다.
  • 데이터 반출은 배포 방식에 달렸다. 온프레미스나 전용망에 두면 통제 범위를 넓힐 수 있다.
  • 유지보수 주체는 UC Berkeley에서 시작해 다수 기관과 기업 기여자가 참여하는 오픈소스 커뮤니티다.
  • 상용 LLM 서빙 플랫폼을 일부 대체할 수 있다. 다만 하드웨어 운영과 튜닝 역량은 내부에서 확보해야 한다.

주요 용어

추론(Inference): 학습된 AI 모델이 실제 입력에 답을 내는 실행 단계 서빙(Serving): 모델을 API나 서비스 형태로 운영 환경에 제공하는 일 배칭(Batching): 여러 요청을 묶어 한 번에 처리하는 방식 양자화(Quantization): 모델 숫자 표현을 줄여 메모리와 연산량을 아끼는 기법 KV 캐시(KV cache): 이전 토큰 계산 결과를 저장해 다음 응답을 빠르게 하는 메모리
