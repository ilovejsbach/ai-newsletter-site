코드 취약점 점검을 CLI로 묶은 OpenAI 도구

★ 10,492TypeScriptApache-2.0 사내 사용 가능릴리스 npm-v0.1.25 (09.02)최근 활동 09.06테스트 없음예제 있음AGENTS.md 있음

OpenAI가 보안 취약점 점검용 도구를 공개했다. 개발자는 터미널에서 저장소를 스캔할 수 있다. 팀은 TypeScript SDK로 같은 기능을 업무 자동화에 넣을 수 있다. 결과를 별도 서비스에 모아 이력과 중복도 관리한다.

무엇을 하는 물건인가

이 저장소는 코드 보안 점검을 자동으로 돌리는 도구다. 코드에서 취약점을 찾고, 실제 문제인지 다시 확인하고, 수정까지 돕는다. 보안 담당자가 저장소마다 점검표를 손으로 모으는 일을 줄여준다. 서류 심사자가 여러 지점 보고서를 한 양식으로 모아 겹친 건을 추리는 모습에 가깝다.

스펙과 도입 조건

  • TypeScript SDK와 CLI를 제공한다.
  • Node.js 22.13.0 이상이 필요하다.
  • Python 3.10 이상이 필요하다.
  • npm 패키지로 설치한다.
  • Docker Compose 예제를 제공한다.
  • CI에서는 OPENAI_API_KEY를 쓴다.
  • 로그인 방식도 지원한다.
  • Amazon Bedrock, OpenRouter, Fireworks를 추론 제공자로 고를 수 있다.
  • 라이선스는 Apache-2.0이다.
  • 최신 릴리스는 npm-v0.1.25이며 2026-09-02에 공개됐다.

이럴 때 쓰면 좋다

  • 인터넷뱅킹이나 앱 백엔드 저장소를 야간 배치로 점검하고 취약점 후보를 아침 회의 전에 모아둘 때 쓸 수 있다.
  • 여러 계열사 저장소에서 나온 보안 이슈가 같은 원인인지 가려서 중복 티켓 발행을 줄일 때 맞다.
  • 사내 보안 기준 문서를 rubric으로 넣고 취약점을 내부 심각도 기준으로 다시 분류할 때 유용하다.

핵심 기능

  • 코드에서 보안 취약점을 찾고 검증한 뒤 수정 작업까지 지원한다.
  • findings service가 결과와 임베딩을 SQLite에 저장하고 중복 후보를 보여준다.
  • classify-severity 기능이 정책 문서를 기준으로 취약점 심각도를 다시 평가한다.

대안 대비 차별점

이 도구는 단순 스캔 결과 출력에서 멈추지 않는다. 완료한 점검 결과를 findings service로 올리면 저장소별 이력과 중복 후보를 관리할 수 있다. 읽기 전용 대시보드는 5초마다 새로고침되며, 각 취약점은 SQLite에 저장된다.

이번 릴리스에서는 확인된 취약점의 식별자를 스캔 사이에 유지한다. 큰 비교 작업은 배치로 나눠 처리한다. 텍스트가 너무 길어 비교를 끝내지 못하면 미완료라고 분명히 표시한다.

중복 정리 방식도 바뀌었다. 사전 선별과 쌍 비교를 나눠 돌린다. DISTINCT로 분리하라고 정한 결과는 그룹에 반영한다. 잘못된 제출에는 한 번 수정 기회를 준다. 막힌 리뷰는 판정을 남기지 않고 실패 처리한다.

인증 없이 모델 호출도 하지 않는 mock 스캔도 새로 들어왔다. 일반 보고서와 내보내기, 이력, 재실행 흐름을 그대로 시험할 수 있다. 실행 중 예산이 한도의 80%에 닿으면 대시보드나 SDK 콜백으로 총예산을 늘릴 수 있다. 저장 전까지는 기존 한도를 그대로 지킨다.

사내 도입 체크

  • 외부 API 호출이 들어간다. OpenAI 로그인이나 OPENAI_API_KEY, 다른 추론 제공자 키가 필요할 수 있다.
  • findings service에 취약점과 저장소 ID를 올릴 수 있다. 데이터 반출 범위와 마스킹 기준을 먼저 정해야 한다.
  • 유지보수 주체는 OpenAI 조직이다.
  • 상용 SAST 도구나 코드 보안 스캐너를 일부 대체할 수 있지만, 탐지 범위와 감사 요구 충족 여부는 별도 확인이 필요하다.

주요 용어

CLI(Command Line Interface): 터미널에서 실행하는 명령형 도구 SDK(Software Development Kit): 다른 프로그램에 기능을 붙일 때 쓰는 개발 도구 모음 CI(Continuous Integration): 코드 변경 때 자동 검사와 배포를 돌리는 개발 절차 임베딩(Embedding): 텍스트나 항목을 숫자 벡터로 바꾼 표현 SQLite(SQLite): 파일 기반으로 동작하는 경량 데이터베이스
