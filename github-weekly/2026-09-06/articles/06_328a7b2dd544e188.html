코드 취약점 점검을 자동화하는 보안 CLI

스타 10,464 · 이번 주 +0 · TypeScript · Apache-2.0 사내 사용 가능 · 최근 릴리스 npm-v0.1.25 (09.02) · 테스트 없음 · 예제 있음 · AGENTS.md 있음

보안 스캔 도구는 경고를 많이 내는 것만으로는 충분하지 않다. 같은 취약점을 반복 보고하면 운영팀이 지친다. 정책에 맞는 심각도 분류와 이력 관리도 필요하다. codex-security는 이런 후속 절차를 CLI와 서비스 형태로 함께 다룬다.

무엇을 하는 물건인가

codex-security는 소스코드의 보안 취약점을 찾고, 결과를 검토하고, 수정 작업까지 돕는 도구다. 개발자가 명령어로 바로 돌릴 수 있고, 다른 시스템에 붙일 SDK도 함께 준다. 여러 저장소를 한꺼번에 훑고 결과를 쌓아두는 흐름도 지원한다. 보안팀이 문서 검토만 하던 일을 자동 분류함에 넣고 우선순위를 매기는 느낌에 가깝다.

스펙과 도입 조건

  • 언어는 TypeScript다.
  • Node.js 22.13.0 이상이 필요하다.
  • Python 3.10 이상이 필요하다.
  • 설치 형태는 npm 패키지와 Docker 이미지다.
  • CLI 로그인 또는 OPENAI_API_KEY가 필요하다. CI에서는 API 키 방식을 쓴다.
  • 다른 추론 제공자도 쓸 수 있다. Amazon Bedrock, OpenRouter, Fireworks용 API 키를 설정할 수 있다.
  • 라이선스는 Apache-2.0이다.
  • 최신 릴리스는 npm-v0.1.25다.

이럴 때 쓰면 좋다

  • 인터넷뱅킹 코드 배포 전에 저장소 여러 개를 한 번에 점검하고 결과를 모아야 할 때 쓸 수 있다.
  • 정보보호팀이 취약점 티켓을 발행하기 전에 사내 심각도 기준 문서로 재분류하려는 상황에 맞다.
  • 같은 취약점이 반복 보고돼 개발팀과 보안팀이 중복 확인에 시간을 쓰는 경우 부담을 줄일 수 있다.

핵심 기능

  • CLI와 SDK로 코드 취약점을 찾고 검증하며 수정 흐름을 실행할 수 있다.
  • findings service는 결과와 임베딩을 SQLite에 저장하고 읽기 전용 대시보드를 제공한다.
  • classify-severity 기능은 정책 문서를 기준으로 선택한 결과의 심각도를 재평가하고 재실행 때 기존 평가를 재사용한다.

대안 대비 차별점

이 저장소는 단순 스캔 도구보다 운영 기능이 많다. 완료된 취약점 결과를 올리고, 중복 후보를 다시 검토해 저장할 수 있다. 저장소 단위뿐 아니라 여러 저장소 범위에서 유사한 결과를 찾는 기능도 있다.

통합 방식도 선택지가 넓다. 개발자는 CLI로 바로 쓰고, 시스템 연동이 필요하면 TypeScript SDK를 붙일 수 있다. 대량 스캔은 Docker Compose 구성을 활용한다. 별도 findings service는 같은 이미지로 띄우되 컨테이너와 상태 볼륨을 분리한다.

이번 릴리스 하이라이트에는 인증 없이 모델 호출도 하지 않는 mock 스캔이 추가됐다. 일반 보고서와 내보내기, 이력, 재실행 흐름도 함께 시험할 수 있다. 스캔 예산이 한도 80%에 닿으면 대시보드나 SDK 콜백으로 총예산을 늘릴 수 있지만, 저장하기 전까지는 기존 한도가 그대로 적용된다.

사내 도입 체크

  • 외부 API 호출이 기본 흐름에 들어간다. OpenAI API 키 또는 다른 제공자 키가 필요하다.
  • findings service는 결과와 임베딩을 SQLite에 저장한다. 코드와 점검 결과의 외부 반출 여부는 배치 위치에 따라 달라져 확인이 필요하다.
  • 유지보수 주체는 OpenAI 조직 저장소다.
  • 상용 SAST와 코드 보안 점검 제품이 대체재가 될 수 있다. 다만 이 저장소는 CLI·SDK·중복 검토 서비스가 한 묶음이라는 점이 다르다.

주요 용어

CLI(Command Line Interface): 화면 메뉴 대신 명령어로 쓰는 실행 방식 SDK(Software Development Kit): 다른 프로그램에 기능을 붙일 때 쓰는 개발 도구 모음 임베딩(Embedding): 텍스트 의미를 숫자 벡터로 바꾼 표현 CI(Continuous Integration): 코드 변경 때마다 자동 검사와 빌드를 돌리는 개발 절차 중복 제거(Deduplication): 같은 이슈를 하나로 묶어 재검토 부담을 줄이는 작업
