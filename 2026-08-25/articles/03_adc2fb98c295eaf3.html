OpenAI, Codex를 오픈 하네스로 넓혔다

OpenAI가 Codex를 앱, CLI, IDE를 넘어 플랫폼으로 쓰는 방법을 공개했다. 핵심은 오픈소스 하네스다. 이 계층이 문맥 유지, 도구 사용, 승인 요청, 실행 경계 설정을 맡는다. 개발팀은 이 하네스를 기존 제품과 워크플로에 붙여 에이전트를 넣을 수 있다.

핵심 브리핑

OpenAI는 Codex의 오픈소스 하네스가 앱, CLI, IDE 확장의 공통 기반이라고 설명했다. 하네스는 작업 이해, 장기 문맥 유지, 관련 정보 확인, 도구 호출, 진행 상황 노출, 실패 처리, 승인 요청, 결과 반환을 맡는다. OpenAI는 모델만 붙이는 것으로는 충분한 에이전트를 만들기 어렵다고 못 박았다.

Codex app-server는 이 기능을 문서화된 클라이언트 프로토콜로 노출한다. 애플리케이션은 스레드를 만들고, 턴을 시작하고, 이벤트를 받고, 승인 요청을 처리할 수 있다. OpenAI는 개발팀이 새 런타임을 처음부터 만들지 말고 Codex를 기반으로 시작할 수 있다고 제안했다.

오픈소스로 공개된 구성요소는 Codex CLI, app-server, 공식 Codex SDK다. 다만 오픈소스는 하네스와 통합 표면에 한정된다. 모델 접근과 관리형 서비스는 별개로 남는다.

통합 방식도 용도별로 나뉜다.

  • 스크립트, CI 작업, 일회성 백그라운드 작업은 codex exec
  • 코드에서 시작·재개·스트리밍이 필요하면 Codex SDK
  • 제품 자체에 에이전트를 넣으려면 Codex app-server

OpenAI는 샘플 운영 앱 Relay도 소개했다. 이 앱은 가상 배송 대시보드 옆에서 에이전트를 돌린다. 애플리케이션이 가진 MCP 도구를 연결하고, 배송 재예약 같은 영향 있는 작업은 사람 승인을 요구한다.

주요 트렌드

OpenAI는 에이전트 경쟁의 기준을 모델 응답에서 실행 구조로 옮기고 있다. 기존 제품 경험을 버리고 범용 채팅으로 옮기기보다, 현업이 이미 보는 대시보드와 기록 시스템 안에 에이전트를 넣으라는 방향이다. 이는 엔터프라이즈 도입의 저항을 줄이려는 전략으로 읽힌다.

오픈소스 공개 범위도 선을 그었다. 하네스와 통합 계층은 열지만 모델 접근과 관리형 서비스는 분리했다. 개발자 생태계는 넓히되 핵심 모델 서비스는 통제하는 구조다.

실사용 사례도 코딩 바깥으로 넓혔다. OpenAI는 보안 조사, 운영 대시보드, 고객지원 콘솔, 내부 업무 앱을 예시로 들었다. Codex를 코딩 도구가 아니라 범용 업무 에이전트 런타임으로 키우려는 신호다.

업계의 움직임

OpenAI는 공개 구현 사례로 GitHub, JetBrains, Cisco를 들었다. GitHub와 JetBrains는 기존 IDE 흐름에 Codex를 넣고 있다. Cisco는 Cisco Cloud Control의 App Builder에서 Codex SDK를 쓴다.

Thrive Holdings와 Crete는 세무 준비 워크플로에 Codex를 적용했다. 이 파일럿은 7,000건의 신고서를 처리했고 준비 시간을 약 3분의 1 줄였다.

시사점과 체크포인트

우리 회사가 에이전트를 업무 시스템에 넣으려면 채팅 화면부터 만들 필요는 없다. 오히려 티켓, 계정, 장애 대응, 승인 대기열처럼 기존 화면을 유지한 채 에이전트 루프만 붙이는 편이 현업 수용성이 높을 수 있다.

검토 포인트는 다음과 같다.

  • 어떤 시스템이 문맥과 기록의 원본이 될지
  • 에이전트가 호출할 도구를 누가 소유하고 감사할지
  • 승인 필수 작업과 자동 처리 작업의 경계를 어디에 둘지
  • 로컬 실행과 관리형 서비스의 분리로 보안 요건을 맞출 수 있는지

OpenAI가 제시한 ARC-AGI-3 수치는 자체 설명에 나온 값이다. retained reasoning과 context compaction을 넣었을 때의 결과이며, 모든 업무에 같은 폭으로 재현된다고 볼 수는 없다. 금융 업무에 쓰려면 감사 로그, 권한 모델, 실패 복구 설계를 별도로 확인해야 한다.

주요 용어

harness: 에이전트가 문맥 유지·도구 호출·승인 요청을 처리하는 실행 계층 Codex SDK: 애플리케이션 코드에서 Codex 작업을 제어하는 개발 도구 app-server: 앱이 로컬 Codex 프로세스와 연결하는 서버 구성요소 MCP services: 애플리케이션이 에이전트에 제공하는 도구 연결 방식 sandbox: 접근 가능한 파일·도구 범위를 제한하는 실행 격리 환경
