OpenAI, Codex를 앱 속 에이전트 하네스로 넓혔다

OpenAI가 Codex를 제품이 아니라 플랫폼으로 쓰는 방법을 설명했다. 중심에는 오픈소스 Codex harness가 있다. 이 하네스는 모델이 맥락을 모으고, 도구를 쓰고, 승인 요청을 하고, 작업을 이어가게 만든다. OpenAI는 이 구조를 기존 업무 제품 안에 넣는 패턴을 강조했다.

핵심 브리핑

OpenAI는 Codex의 공통 기반이 open-source Codex harness라고 설명했다. 이 하네스는 앱, CLI, IDE Extension을 움직이는 실행 계층이다. 역할은 대화 상태 관리, 실행 스트리밍, 도구 사용, sandbox 정책 강제, 승인 요청 처리다. app-server를 쓰면 애플리케이션이 thread 생성, turn 시작, event 수신, 승인 요청 처리를 할 수 있다. OpenAI는 모델 접근과 managed services는 별도이며, 오픈소스로 공개한 것은 하네스와 통합 표면이라고 선을 그었다.

  • codex exec: 스크립트, CI job, 일회성 백그라운드 작업용
  • Codex SDK: 시작, 재개, 스트리밍이 필요한 프로그램 연동용
  • Codex app-server: 제품 안에 에이전트를 넣고 긴 대화와 승인 처리가 필요한 경우

OpenAI는 에이전트를 묶는 방식에 따라 결과가 크게 달라진다고 밝혔다. ARC-AGI-3에서 retained reasoning과 context compaction을 적용하자 GPT-5.6 Sol 점수가 13.3%에서 38.3%로 올랐다. 출력 토큰은 sixfold 줄었다. 이 수치는 OpenAI가 소개한 결과이며, 독립 평가인지 여부는 본문에 없다.

주요 트렌드

이번 글은 범용 코딩 도우미를 더 넓히는 제품 전략을 보여준다. OpenAI는 사용자를 자기 앱으로 끌어오기보다, 다른 회사 제품 안에 Codex를 넣는 길을 열었다. 공개 범위는 오픈 하네스와 SDK, app-server다. 모델 접근과 관리형 서비스는 분리해 두었다. 오픈 통합층과 폐쇄 모델 서비스를 나눠 가져가는 구조가 더 또렷해졌다.

업계의 움직임

OpenAI는 공개 구현 사례도 함께 제시했다. GitHub와 JetBrains는 기존 IDE 흐름에 Codex를 넣고 있다. Cisco는 Cisco Cloud Control의 App Builder에 Codex SDK를 쓴다. Thrive Holdings와 Crete는 세무 준비 워크플로에 Codex를 넣어 pilot에서 7,000 returns를 처리했고 준비 시간은 about a third 줄였다.

시사점과 체크포인트

금융IT 기업이 볼 지점은 모델보다 실행 틀이다. 승인 요청, 도구 호출, 기록 갱신, 업무 화면 복귀가 한 묶음으로 돌아가야 현업이 쓸 수 있다. 범용 채팅창은 빠른 실험에는 좋지만, 운영 시스템과 붙을수록 하네스 설계가 더 중요해진다.

  • 검토 팀: 업무시스템 운영, 정보보호, 개발플랫폼, UX 기획
  • 적용 후보: 운영 대시보드, 보안 조사 화면, 고객지원 콘솔, 내부 심사 도구
  • 확인 질문: 에이전트가 어떤 시스템과 도구를 호출하는가
  • 확인 질문: 어떤 쓰기 작업에 사람 승인을 걸 수 있는가
  • 확인 질문: system of record를 어느 화면이 소유하는가
  • 확인 질문: 대화 상태와 실행 로그를 어떻게 보관하는가

세무 사례처럼 생산성 수치를 제시한 부분은 특정 파일럿 결과다. 우리 회사는 민감 데이터, 권한 체계, 감사 요구사항을 먼저 얹어 작은 범위에서 검증하는 편이 안전하다.

주요 용어

harness: 에이전트가 맥락 유지, 도구 호출, 승인 요청을 수행하게 하는 실행 틀 agent loop: 작업 이해부터 실행·검토까지 반복하는 에이전트 흐름 sandbox: 접근 범위를 제한한 실행 환경 MCP services: 애플리케이션이 에이전트에 연결하는 도구·서비스 인터페이스 Codex SDK: 애플리케이션에서 Codex를 프로그래밍으로 쓰는 개발 도구
