Apodex 1.1, 작은 모델로 복합 업무 성능 올렸다

범용 언어모델은 추론과 요약은 잘한다. 하지만 실제 업무는 파일을 열고, 검색하고, 코드를 실행하며, 실패 뒤에 다시 이어 가야 끝난다. Apodex 1.1은 이런 장기 작업 능력을 별도 과제로 다뤘다. 연구진은 작업 환경 확장과 에이전트 협업 학습을 함께 설계했다.

핵심 브리핑

연구진은 복합 업무에 필요한 능력을 '현실 목표를 향해 검증 가능하게 계속 진전하는 능력'으로 정의했다. Apodex 1.1은 이 능력을 두 축에서 키웠다. 하나는 실행 가능한 파일·검색·코드 환경의 종류와 검증성을 넓히는 환경 확장이다. 다른 하나는 긴 작업을 쪼개고, 병렬로 맡기고, 비동기 결과를 합치고, 다시 계획하는 협업 학습이다.

공유 실행 하니스와 AgentOS가 도구와 에이전트 전반의 작업 상태와 변경 이력을 유지한다. 학습 단계에서는 환경 실행 기록과 협업 흔적을 신뢰도 높은 행동으로 바꾸도록 훈련했다. 연구진은 금융, 과학 연구, 수학, 코딩, 검색 같은 복합 전문 업무에서 Apodex 1.1이 선도 성능권에 들어갔다고 밝혔다. 다만 발췌문에는 개별 벤치마크 이름과 수치가 나오지 않았다.

  • Apodex 1.1 Mini 규모: 350억 파라미터
  • Mini 특징: 로컬 배포가 가능한 형태
  • 적용 영역: 금융, 과학 연구, 수학, 코딩, 검색
  • 비교 조건: 많은 프런티어 시스템보다 훨씬 작은 모델 사용

방법과 결과

핵심 기법은 두 가지다. 연구진은 먼저 실행 환경을 넓혀 에이전트가 파일, 검색, 코드 작업을 실제로 수행하고 검증하게 했다. 그다음 여러 에이전트가 긴 작업을 분해하고 병렬 처리하도록 학습했다. 이때 공유 실행 하니스와 AgentOS가 중간 상태를 이어 붙였다.

결과 요약은 분명하다. 연구진은 Apodex 1.1이 더 큰 프런티어 시스템과 같은 선도 성능권에 들어갔다고 적었다. 350억 파라미터 Mini도 강한 작업 수행 능력을 유지했다고 밝혔다. 다만 발췌문에는 독립 평가인지 자체 측정인지, 어떤 벤치마크를 썼는지, 수치 차이가 얼마인지가 없다. 이 한계는 논문 원문 확인이 필요하다.

업계의 움직임

아직 공개된 반응은 확인되지 않았다.

시사점과 체크포인트

금융IT 기업은 '답을 잘하는 모델'보다 '업무를 끝까지 처리하는 시스템'을 먼저 봐야 한다. 문서 수집, 규정 검색, 코드 실행, 결과 검증이 한 흐름으로 이어지는지 점검할 필요가 있다.

우리 회사라면 다음을 먼저 확인할 만하다.

  • 에이전트가 남기는 작업 상태와 변경 이력을 감사 로그로 저장할 수 있는가
  • 실패 뒤 재시도와 재계획 규칙을 운영팀이 통제할 수 있는가
  • 로컬 배포가 필요한 업무와 외부 API를 써도 되는 업무를 구분했는가
  • 금융·보안 문서 처리에서 검증 가능한 산출물 형식을 정했는가

발췌문에는 성능 수치와 비용이 없다. 실제 도입 검토 전에는 벤치마크 조건, 평가 주체, 온프레미스(사내 서버에 직접 설치해 쓰는 방식) 운영 가능 범위를 따로 확인해야 한다.

주요 용어

에이전트 지능(Agentic Intelligence): 긴 작업을 나누고 실행하며 중간 결과를 다시 계획에 반영하는 능력 작업 상태(Task State): 에이전트가 현재 어디까지 했는지 기록한 정보 변경 이력(Provenance): 어떤 도구와 단계가 결과를 만들었는지 남긴 추적 정보 로컬 배포(Local Deployment): 외부 API 없이 사내나 개인 장비에서 직접 운영하는 방식 파라미터(Parameter): 모델 규모를 가늠할 때 쓰는 내부 가중치 수
