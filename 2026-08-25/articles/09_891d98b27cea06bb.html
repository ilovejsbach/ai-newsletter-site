Apodex 1.1, 작은 모델로 장기 작업 성능 겨냥

대형 언어모델은 추론과 요약에는 강하다. 하지만 실제 업무는 파일을 열고, 검색하고, 코드를 실행하면서 상태를 오래 유지해야 한다. Apodex 1.1은 이 지점을 겨냥했다. 연구진은 검증 가능한 방식으로 장기 작업을 끝내는 능력을 핵심 목표로 제시했다.

핵심 브리핑

Apodex 1.1은 여러 단계를 거치는 일을 처리하도록 만든 에이전트 시스템이다. 연구진은 이 시스템을 두 축으로 확장했다. 하나는 Environment Scaling이다. 이 축은 파일, 검색, 코드 실행 환경의 종류를 늘리고 결과를 검증하기 쉽게 만든다.

다른 축은 Agentic Coordination Scaling이다. 이 축은 긴 작업을 더 작은 하위 과제로 나누고, 병렬로 맡기고, 비동기 결과를 합치고, 중간에 다시 계획하도록 학습한다. 연구진은 공통 실행 장치와 AgentOS를 두어 도구와 에이전트 사이의 작업 상태, 이력 정보를 유지했다.

학습에는 환경 실행 기록과 협업 기록을 함께 썼다. 연구진은 이런 학습 방식이 더 안정적인 행동을 만든다고 설명했다. Apodex 1.1은 금융, 과학 연구, 수학, 코딩, 검색 같은 복합 전문 업무에서 선두 성능 구간에 도달했다고 밝혔다. 다만 본문 발췌에는 구체적 벤치마크 수치와 비교 대상 이름은 없다.

  • Apodex 1.1 Mini는 35B-parameter 모델이다
  • 연구진은 이 모델을 locally deployable form으로 제시했다
  • 연구진은 더 큰 frontier systems보다 substantially smaller model이라고 설명했다

방법과 결과

이 연구의 핵심은 모델 자체만 키우지 않았다는 데 있다. 연구진은 작업 환경을 넓히고, 여러 에이전트가 협업하는 방식을 함께 학습했다. 한 에이전트가 모든 일을 순서대로 처리하는 대신, 하위 과제를 나누고 병렬로 진행한 뒤 다시 통합하는 구조다.

결과 서술은 비교적 분명하다. 연구진은 Apodex 1.1이 복합 전문 업무에서 leading performance band에 들어섰다고 적었다. 35B 규모의 Apodex 1.1 Mini도 강한 작업 수행 능력을 유지했다고 밝혔다. 다만 발췌문에는 벤치마크 이름, 측정 주체 외 검증 여부, 수치 차이, 저자가 인정한 실패 사례는 실리지 않았다. 이 기사만으로는 성능 우위의 크기를 정량 비교하기 어렵다.

업계의 움직임

아직 공개된 반응은 확인되지 않았다.

시사점과 체크포인트

금융IT 기업은 챗봇 성능보다 긴 업무 흐름 완주율을 먼저 봐야 한다. 문서 수집, 규정 검색, 파일 가공, 코드 실행, 검증 로그 저장이 한 흐름으로 묶이는지가 더 중요하다.

우리 회사라면 다음을 먼저 점검할 만하다.

  • 업무 상태를 중간 저장할 시스템이 있는가
  • 도구 호출 이력과 결과 근거를 남길 수 있는가
  • 실패 뒤 재시도와 재계획 규칙을 설계했는가
  • 로컬 배포가 필요할 때 35B급 모델을 돌릴 인프라가 있는가

이 연구는 작은 모델도 시스템 설계에 따라 경쟁력을 낼 수 있음을 시사한다. 반면 구체 수치와 한계가 발췌에 빠져 있다. 도입 판단 전에는 실제 벤치마크, 보안 통제, 감사 추적 가능성을 원문 전체에서 확인해야 한다.

주요 용어

에이전트(Agent): 목표를 받아 도구를 쓰고 여러 단계를 거쳐 작업을 수행하는 AI 시스템 추론(Inference): 학습이 끝난 모델이 입력을 받아 답을 만들거나 행동을 고르는 과정 프로비넌스(Provenance): 어떤 데이터와 도구, 단계로 결과가 나왔는지 남기는 이력 정보 로컬 배포(Local deployment): 외부 클라우드 대신 사내나 개인 장비에서 직접 실행하는 방식 파라미터(Parameter): 모델이 학습한 가중치 수를 뜻하는 규모 지표
