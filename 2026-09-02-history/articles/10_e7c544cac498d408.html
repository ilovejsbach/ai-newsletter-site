취약한 AI 에이전트를 고쳐보는 Quarkus 보안 워크숍

AI 에이전트는 외부 도구를 부르고 데이터를 읽는다. 그래서 일반 웹앱 보안과는 다른 위험이 생긴다. 이번 저장소는 그 위험을 실습으로 익히게 만든 교육용 워크숍이다. 먼저 공격해 보고, 그다음 방어를 적용하는 흐름을 택했다.

핵심 브리핑

이 저장소는 일부러 취약하게 만든 Quarkus 기반 회의 도우미를 공격하고, 다시 방어하도록 구성한 보안 워크숍이다. 대상 애플리케이션은 LangChain4j로 만든 에이전트와 MCP 서버를 포함한다. 개발 언어는 Java다.

핵심 목적은 AI 에이전트의 보안 취약점을 실습으로 이해하는 데 있다. 단순히 안전 수칙을 읽는 형식이 아니다. 먼저 취약한 상태를 재현하고, 이후 방어 설정을 적용해 차이를 확인하는 방식이다.

저장소 소개에는 네 가지 OWASP LLM 주제를 다룬다고 적혀 있다. 다만 발췌에는 각 주제의 세부 항목과 방어 방식은 나오지 않았다. 배포 방식과 라이선스, 지원 모델, 운영 환경 조건도 발췌만으로는 확인되지 않는다.

도입 가치

이 자료의 강점은 추상적인 보안 원칙보다 실제 공격·방어 절차를 먼저 보여준다는 점이다. AI 에이전트와 MCP 서버를 함께 다뤄, 도구 호출이 있는 앱의 위험을 교육하기에 맞다. 자바 기반 조직이라면 기존 백엔드 개발 흐름과 연결해 실습하기 수월할 수 있다.

다만 실제 도입 전에 확인할 정보가 많다. 발췌에는 통합 난이도와 실습 범위, 필요한 계정이나 모델, 실행 방법이 없다. 금융사 환경에서 바로 재현하려면 네트워크 제한과 비밀정보 관리, 로그 마스킹 같은 운영 조건을 별도로 점검해야 한다.

업계의 움직임

공개된 발췌에서는 사용자 반응이나 기업 도입 사례는 확인되지 않았다. 아직 공개된 반응은 확인되지 않았다.

시사점과 체크포인트

우리 회사가 AI 에이전트 기능을 검토한다면, 개발 교육과 보안 검증을 따로 떼지 않는 편이 낫다. 이런 실습형 저장소는 개발팀, 보안팀, 아키텍트가 같은 시나리오로 점검하기 좋다.

검토 항목은 분명하다.

  • 프롬프트 입력이 외부 문서와 도구 호출로 어떻게 이어지는지
  • MCP 서버가 어떤 데이터와 권한을 노출하는지
  • 에이전트가 실행할 수 있는 명령 범위를 어디까지 제한할지
  • 로그와 대화 기록에 민감정보가 남는지
  • 실습용 취약 설정이 운영 환경으로 섞여 들어갈 위험이 있는지

이번 자료는 교육용 저장소 소개 수준이라 세부 보안 범위가 아직 부족하다. 사내 적용 전에는 실습 시나리오와 위협 모델, 재현 절차, 완화책 목록을 직접 확인해야 한다.

주요 용어

Quarkus: 자바 기반 클라우드 애플리케이션 프레임워크 LangChain4j: 자바에서 LLM 애플리케이션을 만들게 돕는 라이브러리 에이전트(Agent): 목표를 받아 도구 호출과 단계 실행을 이어 가는 AI 프로그램 MCP(Model Context Protocol): 모델과 외부 도구·데이터를 연결하는 규약 OWASP LLM: 대형언어모델 앱의 보안 위험을 정리한 OWASP 가이드
