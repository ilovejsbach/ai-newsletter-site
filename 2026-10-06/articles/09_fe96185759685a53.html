AWS, Strands Decider 2B 배포

에이전트는 답변만 하지 않는다. 도구를 호출하고 값을 넘기며 실제 작업을 건드린다. 이때 가장 먼저 필요한 것은 더 긴 답변보다, 지금 실행해도 되는지 빠르게 가르는 판단이다. AWS는 그 용도에 맞춘 소형 결정 모델을 로컬 실행 형태로 공개했다.

핵심 브리핑

Strands Decider 2B는 에이전트Agent — 목표를 받고 도구 호출과 단계 실행을 스스로 이어 가는 AI 소프트웨어가 행동하기 전, 로컬에서 빠르게 한 번 더 점검하는 작은 결정 모델Decision model — 자유 문장 생성 대신 정해진 선택지 중 하나를 고르거나 점수를 매기는 모델이다. 이 모델은 자유 문장을 만들지 않는다. 개발자가 준 선택지 중 하나를 고르거나 점수를 매긴다. 그래서 없는 선택지를 지어내는 일은 막을 수 있다. AWS는 모델과 함께 학습 데이터, 학습 스크립트도 같이 공개했다.

AWS는 이 모델을 지난 목요일 공개했다. 기반 언어이해 모델은 Qwen3.5-2B다. AWS는 여기에 문장 생성용 헤드를 빼고, 선택지 점수화용 포인터 헤드를 붙였다. 이 헤드는 100만 개가 조금 넘는 파라미터를 쓴다. 백본에는 rank-16 LoRALow-Rank Adaptation — 적은 추가 파라미터로 기존 모델을 미세조정하는 방식 어댑터를 적용했다.

AWS가 든 예시는 날씨 질의다. 사용자가 도시를 말하지 않았는데 에이전트가 임의로 도시를 추정하고 날씨 도구를 부르려 하면, Decider가 대화 근거가 있는지 먼저 본다. 정보가 부족하면 애플리케이션은 에이전트에게 사용자가 어느 도시를 뜻하는지 다시 묻게 한다.

Strands의 개입 시스템에서는 개발자가 다음 행동을 고를 수 있다.

  • 도구 호출을 그대로 진행
  • 도구 호출을 거부
  • 사람 확인을 요청
  • 에이전트에 피드백을 반환

이번 데모에서는 Decider가 로컬에서 돈다. 생성형 모델 호출은 Amazon Bedrock을 쓴다. AWS는 결정 모델 연동용 라이브러리도 준비하고 있다고 밝혔다.

AWS는 JevBench 공개 세트에서 성과를 함께 제시했다. AWS 설명에 따르면 Strands Decider는 약 20억 개 파라미터를 쓰는 공개 모델 가운데 2위였다. 학습 레시피를 전부 공개한 공개 모델 가운데서는 1위였다고 밝혔다. AWS는 이 수치를 자체 측정으로 제시했다.

지연 시간도 공개했다.

  • Nvidia RTX 3090에서 100밀리초 미만
  • 작업이 커질수록 응답 시간 증가
  • M3 MacBook의 작은 작업 중앙값은 약 150밀리초

AWS는 지금 모델이 아키텍처의 두 번째 주요 버전이라고 밝혔다. 이전 헤드 설계는 성능이 훨씬 낮았다고 설명했다. 저장소에는 예전 반복 버전도 남겨 뒀다.

도입 가치

기존 생성형 모델만으로 에이전트를 통제하면, 설명은 길어도 실행 전 검사는 느리고 흔들릴 수 있다. 결정 모델은 그 앞단에서 짧은 판단만 맡는다. 도구 호출 전 검증, 출력 평가, 요청 라우팅 같은 작업에 잘 맞는다.

이 방식의 장점은 두 가지다. 먼저 선택지가 정해져 있으니 없는 답을 만들지 않는다. 다음으로 확신 점수를 같이 낼 수 있어, 일정 기준 아래에서는 사람 승인을 붙이는 운영 규칙을 만들기 쉽다. 반면 정답 보장은 아니다. AWS도 선택지 제한이 정확도를 자동으로 보장하지는 않는다고 밝혔다.

도입 난이도는 비교적 낮아 보인다. 모델을 내려받아 로컬에서 돌릴 수 있고, 학습 데이터와 스크립트도 열려 있다. 다만 운영 환경에서는 숙제가 남아 있다. 원문은 프로덕션 투입을 위해서는 클라우드에서 관리형으로 쓰는 호스팅 버전도 필요하다고 짚었다. AWS는 아직 그 제공 여부를 밝히지 않았다.

업계의 움직임

결정 모델 경쟁은 이미 여러 진영으로 번졌다. TypeSafe의 Jev가 최근 흐름을 만들었고, OpenAI는 화요일 제한적 프리뷰로 Decisions API를 내놨다. 다만 OpenAI는 호스팅 API에 초점을 맞췄고, AWS는 내려받아 쓰는 모델과 학습 레시피 공개를 택했다. Kev도 로컬 배포와 미세조정을 지원해, 공개 모델 기반 실험이 빠르게 늘고 있다.

시사점과 체크포인트

우리 회사가 에이전트를 검토한다면, 생성형 모델 성능보다 먼저 실행 통제 지점을 설계해야 한다. 특히 외부 API 호출, 사내 지식 조회, 결재·주문·변경 요청 같은 행동에는 결정 모델을 앞단에 두는 구성이 현실적이다.

체크포인트는 분명하다.

  • 어떤 도구 호출 앞에 사전 검증을 넣을지 정하기
  • 확신 점수 기준으로 자동 실행과 사람 확인을 나누기
  • 로컬 배포가 필요한 데이터 구간을 선별하기
  • Bedrock 같은 생성형 경로와 로컬 결정 경로를 어떻게 나눌지 정하기

미확인 정보도 있다. AWS는 가격과 라이선스 세부 조건을 본문에서 설명하지 않았다. 호스팅 버전 제공 계획도 아직 확정하지 않았다. 벤치마크 수치는 AWS 자체 측정이므로, 내부 파일럿에서 우리 업무 데이터로 다시 검증해야 한다.
