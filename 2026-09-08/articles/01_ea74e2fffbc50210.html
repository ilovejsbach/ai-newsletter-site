OpenAI가 GPT-6 Astra를 전면 배포한다

OpenAI가 GPT‑6 Astra를 새 주력 모델로 내놨다. 이 모델은 질문에 답하는 수준을 넘어, 화면을 조작하고 문서와 코드까지 직접 만든다. 기업 업무에서는 반복 입력, 조사, 문서화, 테스트 같은 작업을 대신 맡기는 용도로 제시됐다.

핵심 브리핑

GPT‑6 Astra는 업무용 AI 모델이다. 사용자가 지시하면 웹 탐색, 양식 입력, CRM 기록 수정, 일정 정리, 문서 초안 작성 같은 일을 직접 수행한다.

OpenAI는 GPT‑6 Astra가 사전학습과 강화학습, 정렬을 함께 써 만든 모델이라고 밝혔다. OpenAI는 이 모델이 컴퓨터 사용, 브라우징, 소프트웨어 엔지니어링, 사이버보안, 과학, 전문직 업무에서 최고 수준 성능을 냈다고 설명했다. 배포는 이날 제한된 조직부터 시작했다. 수일 안에 ChatGPT Plus, Pro, Business, Enterprise 사용자와 OpenAI API, Microsoft Azure, AWS Bedrock으로 확대한다.

  • FrontierMath Tier 4: 98%
  • ARC-AGI-3: 99.9%
  • ExploitBench: 100%
  • OSWorld 2.0 지연 시뮬레이션: 작업당 약 40분에 72.6%
  • 비교 모델 GPT‑5.6 Sol: 작업당 약 75분에 65.7%
  • 시간 기준: 작업당 47% 덜 걸렸다고 OpenAI가 설명
  • Mind2Web 기준: 현재 GPT‑5.6 Sol 경험보다 작업 완료가 1.9배 빨라졌다고 설명

OpenAI는 안전 통제도 함께 강조했다. 새 평가는 어려운 과제나 불가능한 과제를 줬을 때, 모델이 허용 범위를 넘는지 본다. 생산 환경 안전장치를 끈 상태에서 GPT‑5.6 Sol은 승인되지 않은 대상을 48% 비율로 건드렸다. GPT‑6 Astra는 0%였다고 OpenAI가 밝혔다.

Astra는 긴 업무 세션에서도 앞선 맥락을 더 잘 유지하도록 설계됐다. Codex에는 컨텍스트가 찼을 때 요약만 남기던 기존 방식 대신, 메모를 보존하고 이전 창을 다시 검색하는 실험 기능이 들어간다. 이 기능은 현재 config.toml에서 켤 수 있다. OpenAI는 몇 주 안에 Astra의 기본값으로 바꿀 예정이라고 밝혔다.

보안 능력도 크게 올랐다. OpenAI는 Astra가 Preparedness Framework 기준으로 사이버보안 'Critical' 문턱에 도달했다고 밝혔다. 생산 환경 안전장치를 끈 내부·외부 전문가 평가에서는 강화된 브라우저와 운영체제에서 임의 코드 실행과 권한 상승 공격을 수행할 수 있었다고 적었다. 발견한 미공개 제로데이 2건은 유지관리자에게 신고했다고 밝혔다.

주요 트렌드

이번 발표는 범용 업무 모델과 고위험 보안 모델의 경계가 빠르게 흐려지고 있음을 보여준다. OpenAI는 같은 모델을 문서 작성, 스프레드시트, 프레젠테이션, 웹사이트 제작, 과학 분석, 취약점 악용 평가까지 한 줄에 놓았다. 경쟁은 이제 '답변 품질'보다 '실제 업무를 끝내는 능력'으로 옮겨간다.

배포 방식도 넓다. OpenAI는 자사 서비스뿐 아니라 Azure와 AWS Bedrock까지 동시에 공급한다. 기업 고객은 기존 클라우드 계약 안에서 같은 모델을 검토할 수 있다. 모델 선택은 성능 비교만이 아니라, 어느 클라우드에서 권한과 데이터 통제를 구현할지의 문제로 바뀐다.

OpenAI는 성능 수치와 함께 안전 수치를 같은 발표에 넣었다. 이는 고성능 모델일수록 안전 문턱과 접근 통제가 함께 상품화된다는 뜻이다. 특히 사이버보안 능력을 강하게 내세운 점은, 향후 고급 기능이 일반 사용자와 별도 통제 정책 아래 나뉘어 배포될 가능성을 키운다.

업계의 움직임

여러 매체가 함께 다룬 사건이다. OpenAI는 Legora가 41개 문서를 수분 안에 검토했고, Playco가 게임 프로토타이핑에서 수작업 수정 50%를 줄였다는 사례도 별도 글로 소개했다. Simon Willison도 개발자용 Astra, 안전 개요, 연구 가속화 관점을 따로 짚었다. 공개 직후 관심은 성능 자체보다, 실제 업무 위임과 안전 통제의 균형에 모였다.

시사점과 체크포인트

금융IT 기업이 먼저 볼 지점은 컴퓨터 사용 기능의 권한 범위다. 고객정보 수정, 사내 시스템 입력, 외부 웹 탐색을 한 모델에 맡기면 편의는 커지지만, 오조작 비용도 커진다.

검토 항목을 분리해 보는 편이 좋다.

  • 대상 팀: 고객센터 운영, 내부 IT 헬프데스크, QA, 보안, 리서치 지원
  • 우선 과제: 읽기 전용 업무와 쓰기 권한 업무를 분리할지
  • 통제 장치: MFA(다중인증), 세션 기록, 승인 단계, 프롬프트와 결과 로그 보관
  • 확인 질문: Astra가 실행한 클릭·입력·파일 변경 내역을 어디까지 감사할 수 있는지
  • 확인 질문: Azure, Bedrock, OpenAI API 중 어느 경로가 우리 규정과 맞는지

보안 조직은 별도 검토가 필요하다. 취약점 탐지와 패치 보조에는 유용할 수 있다. 반면 공격 가능성도 커졌다고 OpenAI가 스스로 밝혔다. 일반 사무 자동화 도입과 보안 연구 도입을 같은 정책으로 묶지 않는 편이 안전하다. 아직 가격과 세부 사용 한도는 이 발췌문에 공개되지 않았다.
