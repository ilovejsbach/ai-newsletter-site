09 Hugging Face 게시일 2026.09.03

H company, 문서 검색용 NeoMME 공개

이 모델은 텍스트와 문서 이미지를 함께 읽어 검색용 벡터를 만드는 인코더다. 핵심은 PDF를 OCR로 먼저 풀지 않고, 페이지 화면 자체를 이미지로 검색할 수 있다는 점이다. 문서의 글자뿐 아니라 표, 차트, 배치, 글꼴 같은 시각 정보도 함께 쓴다.

핵심 브리핑

H company는 NeoMME를 2종으로 공개했다. 2억 6000만 개와 8억 개 매개변수 모델이다. 두 모델은 텍스트와 이미지 패치를 같은 Transformer 인코더로 처리한다. 별도 비전 타워나 텍스트 생성 디코더를 두지 않는다. 회사는 Hugging Face Transformers에서 모델을 제공한다. 체크포인트는 Apache 2.0 라이선스로 배포한다.

문서 검색용 파생 모델인 NeoMME-Retriever는 페이지 이미지를 바로 검색한다. 이 방식은 PDF에서 텍스트를 뽑는 OCR 전처리를 건너뛴다. 한 번의 추론으로 밀집 임베딩과 지연 상호작용 임베딩을 함께 만든다. 회사는 ViDoRe v3에서 두 모델이 성능과 크기 기준의 파레토 전선에 있다고 밝혔다.

  • 입력 문맥 길이: 1만 6384토큰
  • 이미지 입력: 32×32 패치로 분할
  • 2억 6000만 개 모델 처리량: 초당 약 51페이지
  • 측정 조건: 2048×2048 입력, NVIDIA L40S GPU
  • 처리량 비교: ColModernVBERT의 약 2배
  • 2억 6000만 개 모델 nDCG@10: 0.523
  • 8억 개 모델 nDCG@10: 0.556

저장공간 절감 수치도 함께 제시했다. 회사는 계층형 토큰 풀링과 비대칭 양자화를 조합했다. 그 결과 지연 상호작용 인덱스 저장공간을 문서 페이지당 약 1.5MB에서 6kB로 줄였다고 밝혔다. 감소 폭은 255배다. 이 설정에서도 기준 nDCG@10의 95% 이상을 유지했다고 설명했다.

스펙과 도입 조건

도입 관점에서 가장 큰 특징은 배포 조건이 단순하다는 점이다. 텍스트와 이미지를 같은 계산 경로로 처리하므로, 서로 다른 모델을 이어 붙이는 구조보다 운영 구성이 짧다. 모델은 처음부터 학습했고, 기존 비전 인코더나 언어 디코더를 가져다 붙이지 않았다.

입력 해상도는 고정 비율로 줄이지 않는다. 문서 페이지의 비율과 크기를 유지한다. 정보가 많은 고해상도 페이지에는 더 많은 토큰을 쓴다. 일반 검색에서는 지연 상호작용 임베딩을 권장했다. 문서 집합이 매우 크면 먼저 밀집 임베딩으로 후보를 좁히고, 그다음 지연 상호작용으로 재정렬하라고 제안했다.

고해상도 이미지는 벡터 수가 빠르게 늘어난다. 2048×2048 정사각 페이지는 출력 임베딩이 4200개 벡터를 담는다. float32 기준으로 약 2.1MB다. 회사는 ViDoRe v3 평균이 문서당 약 1.5MB라고 밝혔다.

  • 토크나이저 어휘 수: 13만 1000토큰
  • 사전학습 처리량: 약 5240억 packed 입력 토큰
  • 이 중 텍스트 전용 예시: 2900억 토큰
  • 저장 절감 설정 1: 풀링 계수 10, 질의·문서 int8
  • 저장 절감 결과 1: 페이지당 39kB, 39배 감소, 기준 nDCG@10의 99% 이상 유지
  • 저장 절감 설정 2: 풀링 계수 8, 질의 int8, 문서 binary
  • 저장 절감 결과 2: 페이지당 6kB, 255배 감소, 기준 nDCG@10의 95% 이상 유지

업계의 움직임

이 글은 Hugging Face 블로그에 실렸고, 모델은 Hugging Face Transformers에서 바로 쓸 수 있다. 본문은 ColPali, ColBERT, NextPlaid, ModernVBERT 같은 기존 공개 생태계를 직접 비교 대상으로 삼았다. 다만 고객사 도입 사례나 경쟁사의 공식 대응은 아직 공개되지 않았다.

시사점과 체크포인트

우리 회사가 문서 검색이나 사내 지식 검색을 고도화하려면, OCR 중심 파이프라인을 그대로 둘지부터 다시 볼 필요가 있다. 계약서, 안내문, 스캔 이미지처럼 배치와 표가 중요한 문서는 페이지 이미지 검색이 더 맞을 수 있다.

검토 포인트는 분명하다.

  • 대상 문서에 표, 차트, 서식 정보가 중요한가
  • 기존 OCR 품질이 낮아 검색 누락이 자주 생기는가
  • 대용량 인덱스를 저장할 스토리지 예산이 있는가
  • 초당 약 51페이지 처리량이 우리 적재 속도 요구를 맞추는가
  • 지연 상호작용 인덱스와 ANN 재정렬 구조를 함께 운영할 수 있는가

미확인 정보도 있다. 벤치마크 수치 일부는 회사 자체 평가를 포함한다. 한국어 금융 문서에서의 정확도, 실제 운영 비용, 긴 PDF 묶음 단위 검색 성능은 따로 검증해야 한다.

주요 용어

멀티모달 인코더(Multimodal encoder): 텍스트와 이미지를 같은 모델이 벡터로 바꾸는 인코더 지연 상호작용(Late interaction): 질의 토큰과 문서의 여러 벡터를 나중에 세밀하게 맞춰 점수화하는 검색 방식 밀집 임베딩(Dense embedding): 입력 전체를 소수의 벡터로 압축한 검색 표현 nDCG@10: 상위 10개 검색 결과의 관련도 품질을 재는 지표 양자화(Quantization): 벡터 값을 더 작은 정밀도로 바꿔 저장공간을 줄이는 방법
