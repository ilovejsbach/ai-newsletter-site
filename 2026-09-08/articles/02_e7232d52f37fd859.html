Anthropic, Claude Fable 5.1 공개하고 가격 25% 낮췄다

Anthropic은 새 모델을 성능 경쟁만으로 소개하지 않았다. 비용과 데이터 통제, 안전장치 개선을 한 묶음으로 내놨다. 비개발자 관점에서는 같은 일을 더 싸게 하고, 더 덜 막히게 하며, 민감 데이터를 덜 남기는 방향의 업데이트로 보면 된다.

핵심 브리핑

Claude Fable 5.1과 Claude Mythos 5.1은 같은 모델이지만 안전장치 수준이 다르다. Fable 5.1은 일반 제공한다. Mythos 5.1은 신뢰 접근 프로그램으로만 제공하며, 사이버보안과 생명과학용 통제를 따로 뒀다.

Anthropic은 세 가지 변화를 함께 발표했다. 가격을 낮췄고, 데이터 보존 정책을 손봤고, 안전장치의 오탐도 줄였다.

  • Fable 5.1의 일반적 작업 비용은 Fable 5보다 약 25% 낮아진다고 밝혔다
  • 고에이전트성 작업에서는 절감 폭이 최대 약 45%라고 밝혔다
  • 사이버보안 안전장치는 이전보다 오탐을 60% 줄였다고 밝혔다
  • Claude Code 기본 노력 수준은 High다
  • Claude Cowork와 Claude.ai 기본 노력 수준은 Medium이다

Enterprise Frontier Safeguards는 고객이 통제하는 클라우드에 데이터를 저장하는 방식이다. Anthropic은 이를 올가을 후반부터 기업 고객에 단계적으로 제공할 계획이다. 그전까지는 자격을 갖춘 고객에게 제로 데이터 보존으로 Fable 5.1을 제공한다.

Anthropic은 Fable 5.1이 소프트웨어 취약점을 찾는 데는 쓸 수 있지만, 익스플로잇 개발은 막는다고 밝혔다. 생물학 분야에서는 미국 정부와 함께 접근 프로그램을 만들었고, 과학자 대상 등록을 곧 시작할 계획이다.

주요 트렌드

이번 발표는 모델 성능 경쟁이 기업 운영 조건 경쟁으로 번졌음을 보여준다. Anthropic은 새 모델을 내놓으면서 벤치마크만 강조하지 않았다. 토큰 과금 구조와 데이터 보존, 오탐 감소를 같은 급의 상품 요소로 앞세웠다.

같은 기반 모델을 안전장치 수준별로 나눠 파는 방식도 분명해졌다. 일반 고객은 Fable 5.1을 쓰고, 고위험 연구 영역은 Mythos 5.1로 분리한다. 이 구조는 성능을 하나로 유지하면서 고객군별 통제를 다르게 가져가려는 전략에 가깝다.

파트너 발언도 비용 대비 효율 쪽에 몰렸다. Devin 운영사는 출시 당일 Opus 5 트래픽을 Fable 5.1로 옮긴다고 말했다. Millennium은 수년간 원인을 못 찾은 드문 장애 원인을 Fable 5.1이 찾아냈다고 소개했다.

업계의 움직임

초기 파트너 반응은 강했다. 투자회사 Millennium, 개발 도구 Devin, Canva, Square, Rakuten Medical 등이 내부 테스트 결과를 공개했다. 여러 매체도 이번 발표를 함께 다뤘지만, 일부 평가는 실제 업무에서 이전 모델과 차이가 크지 않다는 시각도 내놨다.

시사점과 체크포인트

우리 회사는 새 모델을 볼 때 성능보다 운영 조건을 먼저 비교할 필요가 있다. 특히 토큰 비용보다 캐시 읽기 가격이 중요한 워크로드인지 확인해야 한다. 긴 세션과 반복 호출이 많다면 체감 비용 차이가 커질 수 있다.

데이터 보존 정책은 법무와 보안, 인프라가 함께 봐야 한다. 고객 통제 클라우드 저장 방식이 실제 사내 기준을 충족하는지, 제공 시점이 우리 도입 일정과 맞는지도 확인해야 한다.

확인 질문은 아래와 같다.

  • 우리 업무는 High와 Medium 중 어느 노력 수준이 맞는가
  • 오탐 60% 감소가 우리 보안 문의나 코드 검토 흐름에도 적용되는가
  • 제로 데이터 보존 자격 조건은 무엇인가
  • 취약점 탐지는 허용하고 익스플로잇 개발은 막는 정책이 사내 연구 흐름과 충돌하지 않는가

Anthropic은 여러 고객 사례를 소개했지만, 다수는 정성 평가다. 독립 평가와 우리 업무 재현 테스트를 따로 해야 한다.

주요 용어

제로 데이터 보존(Zero Data Retention): 서비스 제공자가 입력과 출력을 저장하지 않는 운영 정책 오탐(False Positive): 정상 요청인데 안전장치가 위험하다고 잘못 막는 경우 캐시 읽기(Cache Read): 이미 처리해 저장한 입력을 다시 읽어 쓰는 방식 가드레일(Safeguard): 위험한 사용을 막기 위해 모델 앞뒤에 두는 통제 장치 신뢰 접근 프로그램(Trusted Access Program): 제한된 사용자만 고위험 기능에 접근하게 하는 운영 제도
