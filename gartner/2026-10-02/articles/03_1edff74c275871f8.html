데이터를 누가 소유하고 어떻게 쓸지 정하는 일은 사업 부서의 책임이다. CISO는 그 데이터를 어떻게 보호할지 책임진다. 두 책임이 섞이면 의사결정이 느려지고, 보안 성과도 흐려진다.

핵심 요약

전략 계획 가정 Strategic Planning Assumption

2028년까지 데이터 소유권과 통제 소유권을 분리한 조직은 데이터 이니셔티브를 30% 더 빠르게 추진하고, 데이터 보안data security — 무단 접근, 오용, 변조, 유실을 막기 위해 사람·프로세스·기술 통제를 적용하는 일. 사고는 20% 더 적게 겪을 것이다.

조직은 데이터 거버넌스data governance — 데이터의 소유, 품질, 메타데이터, 계보, 보존, 업무상 사용 원칙을 정하는 운영 체계.의 공백을 사이버보안 문제로 다루지 말아야 한다. AI와 분석, 디지털 전환이 빨라지면서 데이터 거버넌스와 데이터 보안의 경계가 흐려졌다. 그 결과 CISO가 데이터 생성, 소유, 관리, 공유 방식에서 생긴 위험까지 떠안는 경우가 늘었다. 경영진은 데이터 소유 책임과 보호 통제 책임을 분리해 운영해야 한다.

이 대목 전문 펼치기

조직은 데이터 거버넌스의 공백을 사이버보안 문제로 다루지 말아야 한다. 조직이 AI, 분석, 디지털 전환 이니셔티브를 가속할수록 데이터 거버넌스와 데이터 보안의 경계는 점점 흐려진다. CISO는 사업 전반에서 데이터가 생성되고, 소유되고, 관리되고, 공유되는 방식에서 생긴 위험까지 책임지는 처지에 놓인다. 사이버보안 리더는 노출을 줄일 수는 있다. 그러나 데이터 소유가 불분명하거나, 데이터 스튜어드십이 약하거나, 데이터 거버넌스 관행이 부실해서 생긴 위험까지 지속 가능하게 완화할 수는 없다.

데이터 거버넌스의 결함이 사이버보안 책임으로 바뀌지 않게 하려면 CISO는 다음을 해야 한다. 데이터 거버넌스에서 사이버보안 책임의 경계를 정의하고 알려야 한다. 데이터 보호 책임과, 수명주기 전반에서 데이터를 소유·분류·관리하는 책임을 구분해야 한다. 중요 데이터 자산에 명확한 사업 소유자를 세워야 한다. 데이터 거버넌스 결정을 책임지는 지정 소유자가 있는 데이터 자산에 맞춰 보안 투자와 통제를 정렬해야 한다. 명확한 소유자가 없는 데이터는 사이버보안 위험이나 보안팀이 풀 문제로 보지 말고, 관리되지 않는 전사 위험으로 다뤄야 한다. CISO는 데이터 위험이 아니라 사이버보안 위험을 맡는다는 점을 분명히 해야 한다. 데이터 소유자는 사업 위험, 데이터 가치, 사용, 보존 결정에 계속 책임을 진다. 데이터 거버넌스 성과와 데이터 보안 성과를 따로 측정해야 한다. 데이터 거버넌스 지표는 품질, 계보, 사업 가치에 맞춰야 한다. 데이터 보안 지표는 통제 효과, 사이버 위험 감소, 사고 대응 성과, 컴플라이언스 결과에 맞춰야 한다.

문제 맥락

조직이 해결하지 못한 데이터 거버넌스 실패를 CISO 기본 책임으로 돌리는 관행이 문제다. 이 방식은 데이터 소유와 품질, 보존, 사용 결정을 가진 부서의 책임을 흐린다. Gartner는 현재 상황을 세 가지로 설명한다. 역할 혼선, 책임 공백, 규제와 기술 복잡성 증가다.

이 대목 전문 펼치기

조직은 데이터 거버넌스 실패의 희생양으로 CISO를 세우는 일을 멈춰야 한다. 해결되지 않은 모든 데이터 거버넌스 실패의 기본 소유자로 CISO를 두는 것은 중대한 실수다.

CISO는 데이터가 어떻게 생성되고, 보존되고, 공유되고, 사용되는지에 대한 파편화된 소유 구조, 불충분한 스튜어드십, 불명확한 책임을 대신 메울 수 없고, 메워서도 안 된다.

이 접근은 CISO를 실패할 수밖에 없는 위치에 두고, 조직은 구조적 데이터 위험에 더 크게 노출된다. 데이터 보안, 데이터 활용 가치, 규제 감시가 한데 모이면서 사이버보안 리더의 운영 환경은 더 모호해졌다. 현재 상태는 세 가지 동학이 규정한다.

역할 혼선: 경영진은 데이터 보안을 일반 데이터 거버넌스의 하위 영역으로 보는 경우가 늘고 있다. 그 결과 전통적으로 CDAO나 IT 운영이 맡던 데이터 품질, 계보, 스튜어드십의 운영까지 CISO가 맡기를 기대한다. 실제로 사이버보안 및 데이터 보안 리더의 47%는 데이터 품질을 직접 관리하고 개선한다고 답했다. 56%는 데이터 및 분석 팀과 적극 협업해 데이터 보안 정책과 표준을 만든다고 답했다. 74%는 데이터 보안 거버넌스 정책과 표준 수립을 주도한다.

책임 공백: 조직이 AI, 분석, 디지털 전환을 가속할수록 데이터 성과에 대한 책임은 더 파편화된다. 데이터 소유자는 전사 데이터와 관련된 모든 위험을 보안팀이 책임진다고 여기는 경우가 많다. 반면 보안 리더는 데이터 생성, 품질, 보존 결정, 사업상 사용에 대한 권한이 없다. 이 불일치는 운영 마찰을 만들고 의사결정을 약화한다.

규제와 기술 복잡성: 확대되는 프라이버시 규제, 국경 간 데이터 요구, 제3자와의 데이터 공유 증가, 클라우드·SaaS·AI 플랫폼 확산은 민감데이터의 공격면과 컴플라이언스 요구를 크게 늘렸다. 조직은 이에 대응해 CISO 권한을 보안 통제 밖의 데이터, 분석, AI 거버넌스 영역으로 넓히는 경우가 많다. 그 결과 역할은 더 모호해지고, 사이버 위험 관리에 대한 집중은 희석된다.

영향

책임 경계가 흐리면 CISO는 직접 통제하지 않는 결과까지 책임지게 된다. 데이터 품질과 분류, 보존, 접근 승인 문제가 보안팀 성과지표에 섞이면 보안 프로그램의 가치도 증명하기 어려워진다. 반대로 경계를 분명히 하면 데이터 중심 보안 구조를 적용해 통제를 일관되게 유지할 수 있다. 그때 CISO는 데이터 수명주기를 직접 소유하지 않아도 안전한 활용을 지원하는 파트너로 움직일 수 있다.

이 대목 전문 펼치기

데이터 보안에서 CISO의 통제 범위는 사업 부서가 소유한 데이터 거버넌스 결정이 아니라, CISO가 책임지는 사이버보안 위험과 사이버보안 정책, 기술·운영 통제를 뜻한다.

CISO가 자신의 통제 범위를 정의해야 할 필요는 즉각적이다. 데이터 거버넌스와 데이터 보안의 책임이 흐려지면 조직과 운영 양쪽에서 결과가 생긴다.

CISO는 자신이 직접 통제하지 않는 결과까지 책임지게 된다. 여기에는 데이터 품질, 조직 전반에서 데이터를 평가·분류·관리하는 프로세스, 데이터 보존 결정, 사업상 접근 요구가 포함된다.

CISO 책임을 사업 부서가 소유한 데이터 거버넌스 활동까지 넓히면, 사이버 위험 관리와 보안 통제 효과에 쏟아야 할 집중이 약해질 수 있다.

여러 이해관계자가 데이터 관련 이니셔티브의 소유권을 두고 경쟁하면 의사결정 속도는 느려진다. 그 결과 조직 민첩성이 떨어지고, 혁신이 지연되며, 고객 가치 제공과 시장 경쟁력 유지도 어려워진다.

성공 지표가 사이버 위험 감소가 아니라 거버넌스 성과에 묶이면, 데이터 보안 프로그램은 측정 가능한 가치를 증명하기 어렵다.

데이터 결정의 소유권과 사이버보안 통제의 소유권이 분명하지 않으면 규제 준수 활동은 파편화될 수 있다. 그때는 누가 책임지는지 판단하기 어렵고, 컴플라이언스 의무를 포괄적으로 평가하기도 어렵고, 모든 규제와 법정 요구를 빠짐없이 다루기도 어렵다.

반대로 경계를 분명히 정하면 전략적 기회가 생긴다. CISO는 Data Security 참조 아키텍처에 따라 데이터 중심 보안 구조를 채택해, 데이터 수명주기 자체를 소유하지 않아도 다양한 애플리케이션에 일관된 통제를 적용할 수 있다. 이 접근은 사이버보안 리더가 안전한 데이터 활용을 가능하게 하는 전략 파트너로 전환하게 한다. 데이터 거버넌스와 데이터 보안의 소유 경계를 분명히 정한 조직은 책임 구조를 더 강하게 세우고, 데이터 기반 이니셔티브를 더 빠르게 추진하며, 민감정보 보호도 개선한다.

시사점

데이터 거버넌스는 데이터의 의미와 사용 원칙을 정하고, 데이터 보안은 그 데이터를 보호한다. CDAO는 데이터가 무엇을 뜻하고 어떻게 써야 하는지 정한다. CISO는 법률과 규제, 사업 요구에 맞춰 어떤 보안 통제가 필요한지 정한다. CISO는 수명주기 전 단계에서 요구사항과 통제를 정의·감독하지만, 모든 데이터 결정의 소유자는 아니다.

이 대목 전문 펼치기

데이터 거버넌스와 데이터 보안은 서로 보완하는 분야다. 그러나 두 영역은 근본적으로 다른 문제를 푼다. 조직은 누가 데이터 분류 결정을 내릴지, 보존 요건을 정할지, 접근을 승인할지, 규제 의무를 맡을지 같은 의사결정 권한이 불분명할 때 자주 충돌한다. 이 문제는 데이터 및 분석 플랫폼, DLP 솔루션, DSPMdata security posture management — 데이터 저장 위치와 노출 상태, 접근 통제를 점검하는 보안 관리 도구. 도구처럼 기능이 겹치는 도구가 늘면서 더 커진다. 이런 도구는 데이터 탐색, 분류, 접근 모니터링 같은 비슷한 기능을 제공하는 경우가 많다. 기능이 수렴할수록 데이터 거버넌스 팀과 보안 팀의 책임 경계는 더 흐려지고, 도구 소유권과 정책 집행, 데이터 수명주기 관리 책임도 혼란스러워진다.

이 상황은 비정형 데이터가 많을수록 더 복잡해진다. 이메일, 문서, 이미지, 채팅 로그 같은 비정형 데이터는 일관된 메타데이터와 구조가 부족하다. 그래서 데이터 수명주기 전반에서 어떤 역할이나 팀이 거버넌스와 보안 업무를 맡는지 정하기가 훨씬 어렵다. 특히 정형 데이터와 비정형 데이터가 함께 있는 환경에서는, 명확한 책임 체계와 역할 구분이 없으면 데이터 거버넌스와 데이터 보안 모두 효과가 떨어진다.

데이터 거버넌스는 정보가 어떻게 사업 가치를 만드는지 정한다. 초점은 데이터 자산의 소유, 스튜어드십, 품질, 메타데이터, 계보, 보존, 적절한 사업상 사용에 있다. 이런 결정은 보통 사업 이해관계자가 주도하고, CDAO나 CDO 또는 이에 준하는 리더가 조정한다.

반대로 데이터 보안은 데이터를 무단 접근, 오용, 변조, 유실로부터 보호하는 데 초점을 둔다. CISO는 데이터 수명주기 전반에서 사이버 위험을 관리할 수 있도록 사람, 프로세스, 기술 전반에 걸쳐 필요한 통제가 존재하도록 책임진다.

구분을 간단히 하면 이렇다. CDAO는 데이터가 무엇을 뜻하며 어떻게 써야 하는지 결정한다. CISO는 법률, 규제, 컴플라이언스, 사업 요구에 맞춰 적절한 데이터 보안 통제를 정의함으로써 데이터를 어떻게 보호할지 결정한다.

CISO는 통제를 소유한다. CDAO는 의미를 소유한다. 둘은 보조를 맞추지 않으면 성과를 낼 수 없다.

CISO의 통제 범위는 거버넌스, 사이버 위험 관리, 정책 방향, 데이터 보안 관행 감독을 통해 데이터 수명주기 전체에 걸친다. 그렇다고 모든 통제를 직접 소유하거나 운영 실행을 맡는다는 뜻은 아니다. CISO는 적절한 사이버보안 요구사항이 정의되고 집행되도록 보장한다.

데이터 생성·수집 단계에서 CISO는 법률, 규제, 프라이버시, 사업 요구에 맞는 안전한 수집을 위한 보안 요구사항을 정의한다. security-by-design과 privacy-by-design 원칙 적용을 자문한다. 사업 부서가 정한 데이터 분류에 맞춰 보안 보호 수준을 정렬해 통제가 일관되게 실행되게 한다.

데이터 저장 단계에서는 암호화, 키 관리, 저장 보호 요구사항을 정의한다. 안전한 아키텍처를 검증한다. 승인되지 않은 저장소와 섀도 데이터 저장소를 모니터링한다.

데이터 접근·사용 단계에서는 전반적 데이터에 대한 접근 통제와 최소권한 통제를 구현한다. 이상 접근과 무단 사용을 모니터링한다. 데이터 처리와 DLP 정책을 집행한다.

데이터 공유·이전 단계에서는 파트너, 공급업체, 제3자와의 데이터 교환을 보호한다. API, 연계, 국경 간 이전과 관련한 데이터 보안 위험을 이해관계자에게 자문한다. 데이터 이동을 보호하기 위한 모니터링과 암호화 통제를 구현한다.

데이터 보관·보존 단계에서는 아카이브 데이터에 필요한 보안과 접근 통제 요구사항이 정의되도록 한다. 보존 관행에 대한 컴플라이언스 지침을 제공한다. 다만 보존 결정의 소유권은 사업, 법무, 기록관리, 거버넌스 이해관계자에게 있다는 점을 인정한다.

데이터 폐기 단계에서는 안전한 파기와 소거 요구사항을 정한다. 권한 있는 사업·거버넌스 이해관계자가 보존과 폐기 결정을 내린 뒤, 안전한 폐기 통제가 제대로 작동하는지 검증한다.

모든 단계에서 CISO는 적절한 데이터 보안 통제를 수립할 책임이 있다. IT 팀은 보통 그 통제를 실행하고 유지한다. 사업 이해관계자는 사업 목적과 소유권 결정에 계속 책임을 진다.

CISO는 추가 활동까지 떠맡는 대신 다음을 해야 한다. 첫째, 의사결정을 다른 소유자에게 제안하고 위임해야 한다. 정보보안 의사결정 권한, 책임, 업무 소유권을 사업 기능 전반에 걸쳐 분명히 하는 위임 체계를 세우고 감독해야 한다. 주된 결정권자가 부재하거나 이해상충이 있거나 필요한 전문성이 없을 때, CISO는 대체 소유자를 제안하고 승인할 책임이 있다.

둘째, RASCI책임 수행, 최종 책임, 지원, 협의, 통보 대상을 나눠 역할을 문서로 고정하는 매트릭스. 매트릭스로 책임을 공식화해야 한다. 통제 범위를 유지하려면 정식 헌장과 RASCI 매트릭스를 통해 직무 분리를 제도화해야 한다.

셋째, 기능 간 데이터 거버넌스 위원회를 만들어야 한다. CISO, CDAO, 프라이버시 리더, 법무팀, 사업 이해관계자가 참여하는 정례 데이터 거버넌스 운영위원회를 만들거나 참여해야 한다. 이 위원회는 책임 분쟁을 풀고 투자 우선순위를 정한다.

넷째, 성과지표와 ODM을 따로 측정해야 한다. 데이터 거버넌스 지표는 품질, 완전성, 계보, 사업 가치에 맞춰야 한다. 데이터 보안 지표는 통제 효과, 사이버 위험 감소, 사고 빈도, 컴플라이언스 성과에 맞춰야 한다.

지표를 분리하면 보안팀이 자신이 소유하지 않은 결과로 평가받는 일을 막을 수 있다. 동시에 데이터 거버넌스 기능 전반의 투명성도 높아진다.

CISO는 데이터 위험을 소유하지 않는다. CISO는 데이터 수명주기 각 단계에서 전사 데이터를 보호하는 데 수반되는 사이버보안 위험을 소유한다. 데이터 소유자는 사업 위험과 사업 성과, 데이터 사용·보존·가치에 대한 결정에 계속 책임을 진다. 효과적인 데이터 보호에는 모든 이해관계자의 공동 책임이 필요하다.

이 구분을 조직 안에 내재화한 조직은 혁신 속도를 더 높이고, 컴플라이언스를 더 강화하며, 데이터 보안 사고도 실질적으로 더 줄일 수 있다.
