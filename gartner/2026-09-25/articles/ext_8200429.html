새 MCP 개정판의 의미와 준비 과제는?

새 MCP 규격, 구축은 단순화하고 거버넌스는 요구

MCP 프로젝트는 2026년 7월 28일 버전 2026-07-28을 공개했다. 서버와 클라이언트 제공업체는 이를 순차적으로 구현하므로 기존 배치는 계속 동작하며, 사용 중단 유예 기간도 계획된 이전에 충분한 시간을 준다. 다만 많은 기업은 MCP 서버 자산을 파악하거나 추적하지 못해 예기치 않은 장애와 기술 부채에 취약하다. 무상태 상호작용 모델과 강화된 인증 체계는 부하 분산, 정책 적용, 워크로드 신원 관리와 거버넌스를 더 쉽게 만든다.

MCP 준비 태세에 필요한 자산 목록, 통합, 거버넌스

2026-07-28 개정판 도입은 일반적인 로드맵과 출시 계획에 따라 준비하고, MCP 서버·클라이언트 제공업체의 지원 시점을 확인해야 한다. 조직이 제공한 것과 사업부의 음성 배치를 포함해 사용 중인 모든 MCP 서버와 클라이언트를 목록화하고, 규격 버전과 전송 방식까지 기록해야 한다. 기존 게이트웨이와 API 관리 체계가 MCP를 지원하도록 갱신해 트래픽을 통제 범위에 두고, 승인된 서버·클라이언트 목록과 AI 게이트웨이 또는 SASE 통제 적용 위치를 정해야 한다. 보안 검토 기준도 갱신해 IAM 팀과 함께 인증 방식, 클라이언트 등록, 기계 자격 증명을 점검해야 한다.

거버넌스 격차가 커지기 전에 MCP 에이전트 따라잡기

지금 MCP 서버를 목록화하고 거버넌스하지 못하는 조직은 앞으로 이를 소비하는 에이전트도 통제하지 못하게 된다. 프로토콜의 소비자이자 제공자로서 MCP의 가치를 확보하는 결정적 요소는 API 관리 규율이다. MCP는 클라이언트와 서버 사이의 통신 계층일 뿐이며 거버넌스는 규격 바깥에 있으므로, 이번 개정판은 기업 전반의 불균형한 통제 격차를 메우는 계기가 된다. 이미 엔지니어링 리더의 70%가 MCP 서버에서 성과를 보고한 만큼, 거버넌스가 늦으면 에이전트와 경쟁 우위를 함께 놓칠 수 있다.

MCP 가치가 놓이는 지점의 명확한 이해

MCP는 원래 로컬 도구를 단일 클라이언트에 연결하는 데스크톱 프로토콜로 시작했으며, 원격 운영과 보안은 나중에 더해졌다. 내부 통제 시스템처럼 하나의 프레임워크로 도구를 직접 묶는 환경에서는 가치가 상대적으로 작을 수 있다. 반면 기업 간 경계를 넘는 B2C, B2B, B2E 환경에서 예측하기 어려운 에이전트 플랫폼에 기능을 노출하는 제공자 측면이 지속적인 기업 가치의 중심이다. 이번 개정판은 핵심 프로토콜의 무상태화, 인증 강화, 확장 기능의 정식화라는 세 가지 변화로 이러한 서버에 필요한 단순한 구축과 강화된 보호를 제공한다.

성능과 보호 제공을 위한 MCP 제공업체의 상품 업그레이드

1등급 소프트웨어 개발 키트는 구형 프로토콜과의 상호운용성을 유지하지만, 이번 개정판 채택에는 프로토콜 수준의 비호환 변경이 포함된다. 확장성 이점도 세션 가정을 제거한 뒤에야 본격적으로 얻을 수 있다. 기업 구매자는 보안 검토에서 MCP 인증 적합성, CIMD 등록, 발급자 검증을 시험하기 시작할 것이다. 일부 공급업체가 권하는 'API에서 MCP 서버 생성' 방식은 에이전트를 혼란스럽게 하고 불필요한 작업 노출을 늘릴 수 있어, 도메인별로 작고 범위가 명확한 작업 지향 도구 집합을 설계해야 한다.

2026 개정판 가치 확보를 위한 MCP 소비 조직의 도입 현대화

속도와 보안을 높이고 진화하는 MCP 환경의 위험을 줄이려면, 조직은 클라이언트와 서버 구현에서 새 MCP 규격을 채택해야 한다. 이렇게 해야 더 빠른 연결, 더 나은 신뢰성, 더 정돈된 기업 로그인 환경을 제공할 수 있으며, 그렇지 않으면 MCP 서버 접근이 제한될 수 있다. 또한 가시성과 통제를 핵심 과제로 삼아 API 관리 플랫폼, AI 및 MCP 게이트웨이, 네트워크 경계를 넘는 구간의 SASE 정책을 활용해야 한다. 소프트웨어 엔지니어링 팀과 AI 코딩 에이전트가 쓰는 것을 포함해 MCP 클라이언트의 새 규격 지원 여부도 추적해야 한다.

MCP 도입에 IAM을 참여시켜야 하는 엔지니어링 리더의 과제

이번 개정판의 인증 변경은 엔지니어링 팀과 IAM 팀이 함께 책임져야 할 영역으로 의사결정을 옮긴다. 선택형 EMA 확장은 어떤 사용자와 MCP 클라이언트가 특정 MCP 서버에 접근할 수 있는지 기업 신원 제공자가 중앙에서 통제하게 해준다. DCR에서 CIMD로의 전환, 강화된 발급자 검증, 자격 증명과 인증 서버의 더 긴밀한 결합은 조직 경계를 넘나드는 단기 수명 MCP 클라이언트·에이전트·도구에 대한 IAM을 강화한다. 두 팀은 워크로드 신원 통제로 클라이언트 등록, 기계 자격 증명, 별도 식별된 자율 에이전트를 공동 관리하고, 이전 기간에는 버전이 혼재한 환경을 계획해야 한다.

거버넌스된 워크로드와 신원 상호운용성의 미래 논의를 위한 업계 리더 참여

이 변화는 에이전트와 MCP 연결 서비스를 관리되지 않는 API 소비자가 아니라 거버넌스된 워크로드로 다루라는 Gartner의 권고에 더 가까이 다가가게 한다. EMA는 새롭게 부상하는 신원 단언 JWT 인증 부여를 기반으로 하며, IETF와 OpenID Foundation 같은 조직 전반의 표준 작업도 상호운용 가능한 에이전트·워크로드 신원의 기반을 성숙시키고 있다. Gartner와 OpenID Foundation은 라스베이거스의 Gartner Identity & Access Management Summit에서 OAuth 2.1, CIMD, EMA 전반의 상호운용성을 시연하는 행사를 공동 개최한다. 참석 등록이 열려 있다.
