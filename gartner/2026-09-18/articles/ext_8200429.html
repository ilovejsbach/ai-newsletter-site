새 MCP 개정판에 어떻게 대비할까

새 MCP 명세, 구축 단순화와 거버넌스 요구

Model Context Protocol(MCP) 프로젝트는 2026년 7월 28일 버전 2026-07-28을 공개했다. 서버와 클라이언트 제공자는 이를 순차적으로 구현하므로 기존 배치는 계속 동작하며, 사용 중단 유예 기간도 계획된 이전이 가능할 만큼 충분하다. 그러나 많은 기업은 MCP 서버 자산을 목록화·추적하지 않아 이전이 무계획적으로 진행되고, 예기치 않은 장애와 기술 부채에 취약하다. 상태 비저장 MCP 서버는 초기 연결 절차와 서버 종속성이 없어져 부하 분산이 쉬워지고, 헤더의 메서드·도구 이름으로 본문 해석 없이 라우팅·계량·정책 적용이 가능하다. HTTP에서 인가를 쓰는 보호된 MCP 서버는 OAuth 2.1 리소스 서버 역할을 유지하며, 발급자 검증 강화와 DCR의 CIMD 대체로 단기 수명 MCP 클라이언트의 워크로드 신원 관리와 거버넌스가 강화된다.

MCP 준비에는 목록화, 통합, 거버넌스 필요

2026-07-28 개정판 도입은 일반적인 로드맵과 출시 계획에 따라 추진하고, MCP 서버·클라이언트 제공자에게 지원 시점을 확인해야 한다. 조직이 제공하는 것뿐 아니라 사업부의 비공식 배치까지 포함해 사용 중인 모든 MCP 서버와 클라이언트를 목록화하고, 명세 버전과 전송 방식도 기록해야 한다. 기존 게이트웨이와 API 관리 자산이 MCP를 지원하도록 갱신해 MCP 트래픽을 통제 범위에 넣어야 한다. 승인된 서버·클라이언트 목록을 정하고, AI 게이트웨이 또는 보안 접근 서비스 에지(SASE) 통제를 어디에 적용할지도 결정해야 한다. IAM 팀과 함께 MCP 인가가 요구 기준을 충족하는지 점검하고, 애플리케이션·워크로드 신원 통제로 MCP 클라이언트 등록과 기계 자격 증명을 관리해야 한다.

거버넌스 격차가 커지기 전에 MCP 에이전트 대응

지금 MCP 서버를 목록화하고 거버넌스할 수 없는 조직은 앞으로 이를 사용하는 에이전트를 통제하지 못한다. 프로토콜의 소비자이자 제공자로서 MCP의 가치를 확보하는 결정적 요인은 API 관리 규율이다. MCP는 클라이언트와 서버 사이의 통신 계층일 뿐이며, 거버넌스는 이 명세 바깥에 있다. 게이트웨이와 API 관리 지원은 1년 넘게 존재했지만 기업 전반의 적용 범위는 고르지 않으므로, 이번 출시를 그 격차를 줄이는 계기로 삼아야 한다. 엔지니어링 리더의 70%가 이미 MCP 서버로 성과를 보고했으며, 최신 MCP 출시로 에이전트 도입은 더 빨라질 가능성이 크다.

MCP 가치가 놓인 지점의 명확한 이해

MCP는 처음에 로컬 도구를 단일 클라이언트에 연결하는 데스크톱 프로토콜로 시작했고, 원격 운영과 보안은 뒤늦게 더해졌다. 내부 통제 시스템처럼 하나의 프레임워크로 도구를 직접 묶는 환경에서는 가치가 상대적으로 작을 수 있다. 기업에서 지속되는 가치는 제공자 측에 있으며, B2C·B2B·B2E와 회사 경계를 넘는 환경에서 예측하기 어려운 에이전트 플랫폼에 기능을 노출하는 데 있다. 이번 개정은 핵심 프로토콜의 상태 비저장화, 인가 강화, 확장의 공식화라는 세 가지 변화를 담고 있다. 초기화 연결 절차와 세션 헤더가 사라져 서버 확장이 쉬워졌고, 발급자 정보 검증과 DCR의 CIMD 대체로 인가가 강화됐으며, Tasks·MCP Apps·Enterprise-Managed Authorization(EMA)은 각자 일정에 따라 발전하는 확장으로 정식화됐다.

MCP 제공자의 성능·보호 제공을 위한 제품 업그레이드 필요

Tier 1 SDK는 이전 프로토콜과의 상호운용성을 유지하지만, 이번 개정판 도입에는 프로토콜 호환성 단절이 포함되며 세션 가정을 제거해야만 확장성 이점이 온다. 기업 구매자는 보안 검토에서 MCP 인가 적합성, CIMD 등록, 발급자 검증을 시험하기 시작할 것이다. 일부 공급자가 내세우는 'API에서 MCP 서버 생성' 방식은 피하는 편이 낫다. API 카탈로그를 자동 포장하면 에이전트를 혼란스럽게 하는 과도한 도구 표면이 생기고, 접근해서는 안 될 작업까지 노출할 수 있다. 도메인별로 범위가 좁고 작업 지향적인 소수의 도구를 설계하고, 각각을 공개 API처럼 검토해야 한다.

2026 개정판 가치 확보를 위한 MCP 소비 조직의 도입 현대화

속도와 보안을 높이고 변화하는 MCP 환경의 위험을 줄이려면 조직은 클라이언트와 서버 구현에서 새 MCP 명세를 채택해야 한다. 이렇게 하면 더 빠른 연결, 더 나은 신뢰성, 더 정돈된 기업용 로그인 경험을 제공할 수 있으며, 채택하지 않으면 MCP 서버 접근이 어려워질 수 있다. 가시성과 통제를 핵심 과제로 두어야 하며, API 관리 플랫폼은 2025년까지 MCP 지원을 추가했고 AI·MCP 게이트웨이는 전용 통제 지점으로 떠오르고 있다. 트래픽이 네트워크 경계를 넘는 곳에서는 SASE 정책이 보안과 거버넌스가 데이터를 따라가도록 보장한다. 소프트웨어 엔지니어링 팀과 AI 코딩 에이전트가 쓰는 것을 포함해 MCP 클라이언트의 새 명세 지원 여부도 추적해야 한다.

엔지니어링 리더의 MCP 도입에 대한 IAM 연계 필요

이번 개정의 인가 변화는 엔지니어링 팀과 IAM 팀이 함께 책임져야 할 영역으로 의사결정을 옮긴다. 선택적 EMA 확장은 기업 신원 제공자가 어떤 사용자와 MCP 클라이언트가 특정 MCP 서버 접근 권한을 받을 수 있는지 중앙에서 통제하게 한다. DCR에서 CIMD로의 전환, 더 강한 발급자 검증 요구, 인가 서버와 자격 증명의 더 긴밀한 결합은 조직 경계를 넘나드는 단기 수명 MCP 클라이언트·에이전트·도구에 대한 IAM을 강화한다. 엔지니어링 팀과 IAM 팀은 워크로드 신원 통제로 MCP 클라이언트 등록, 기계 자격 증명, 별도로 식별되는 자율 에이전트를 공동으로 거버넌스해야 한다. 도입이 확산되면서 분절된 인가 구조는 중단하고, 이전 기간에는 버전이 혼재한 환경을 계획해야 한다.

거버넌스된 워크로드와 신원 상호운용성의 미래 논의 참여

이 변화는 에이전트와 MCP로 연결된 서비스를 관리되지 않는 API 소비자가 아니라 거버넌스된 워크로드로 다루라는 Gartner의 권고에 MCP를 더 가깝게 만든다. EMA는 새롭게 떠오르는 Identity Assertion JWT Authorization Grant 위에 구축되며, IETF와 OpenID Foundation 같은 조직의 폭넓은 표준 작업도 상호운용 가능한 에이전트·워크로드 신원의 기반을 성숙시키고 있다. Gartner와 OpenID Foundation은 Las Vegas의 Gartner Identity & Access Management Summit에서 OAuth 2.1, CIMD, EMA 전반의 상호운용성을 시연하는 행사를 공동 개최한다. 참석 등록이 가능하다.
