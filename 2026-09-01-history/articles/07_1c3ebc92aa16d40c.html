코드가 세계를 굴리고 영상 모델이 화면을 만든다

영상 생성 모델은 멋진 장면을 만들 수 있지만, 세계의 규칙을 오래 유지하는 일은 아직 약하다. 문이 열렸으면 다음 장면에서도 열려 있어야 하고, 물건이 옮겨졌으면 그 결과가 계속 남아야 한다. 이 연구는 그런 상태 관리를 코드에 맡기고, 영상 모델은 화면 표현에 집중시키는 방식을 제안했다.

핵심 브리핑

Code World Model은 세계의 변화와 화면 생성을 분리하는 연구다. 코딩 에이전트가 사건의 결과를 추론하고, 실행 가능한 코드를 만들어 세계 상태를 유지한다. 비디오 모델은 그 상태를 바탕으로 화면을 렌더링한다. 연구팀은 기존 비디오 기반 세계모델이 시각 관찰만으로 규칙과 원인을 배우려 해 한계가 있었다고 봤다.

이 구조에서 핵심은 프록시 표현이다. 연구팀은 프레임 단위의 시공간 제약을 담는 중간 표현을 만들었다. 이 표현을 프록시 비디오로 컴파일한 뒤, 비디오 모델의 조건 입력으로 넣었다. 즉 코드가 만든 규칙과 상태를 비디오 모델이 읽을 수 있는 형태로 바꿔 연결한 셈이다.

연구팀은 게임플레이와 실제 영상에서 프록시-관측 쌍을 만드는 데이터 파이프라인도 구축했다. 이어 짝지은 게임플레이 데이터로 MiniMax-H3를 미세조정했다. 그 결과 MiniMax-H3가 코딩 에이전트가 만든 단순한 상호작용 세계의 프록시 기반 시공간 규격을 따라갔다고 보고했다. 시각적 디테일과 동적 움직임도 유지했다고 설명했다.

방법과 결과

방법은 역할 분리다. 언어모델 기반 코딩 에이전트가 세계의 규칙, 사건, 후속 상태를 다룬다. 비디오 모델은 최종 시각화만 담당한다. 이렇게 나누면 장면 겉모습과 세계 내부 상태를 같은 모델 하나에 억지로 담지 않아도 된다.

결과도 그 분리 구조에 맞춰 제시됐다. 연구팀은 paired gameplay data로 미세조정한 뒤, MiniMax-H3가 프록시 기반 시공간 제약을 따랐다고 밝혔다. 다만 수치 벤치마크나 비교 대상 점수는 발췌문에 없다. 따라서 성능 우위를 정량으로 판단하기는 어렵다. 공개 내용만 보면 가능성을 보인 개념 검증에 가깝다.

저자가 인정한 한계도 읽힌다. 기존 접근의 한계는 규칙과 메커니즘을 영상만으로 학습하기 어렵다는 점이다. 이번 방법은 이를 코드로 보완했지만, 실제로 얼마나 복잡한 개방형 세계까지 확장되는지는 아직 확인되지 않았다. 실제 환경 영상 데이터에서 같은 일관성이 유지되는지도 더 검증이 필요하다.

업계의 움직임

아직 공개된 반응은 확인되지 않았다.

시사점과 체크포인트

금융IT 관점에서는 이 연구를 바로 제품 후보로 보기보다, 상태 일관성이 필요한 시뮬레이션 기술로 보는 편이 맞다. 예를 들면 상담 훈련, 사고 대응 훈련, 업무 시나리오 재현처럼 이전 사건의 결과가 계속 남아야 하는 콘텐츠에 응용 여지가 있다. 영상만 자연스럽게 만드는 모델보다, 규칙을 코드로 남기는 구조가 감사와 수정에 유리할 수 있다.

우리 회사라면 이런 질문을 먼저 확인해야 한다.

  • 교육콘텐츠팀: 상태 변화가 중요한 시나리오가 실제로 있는가.
  • AI연구팀: 코드가 만든 상태를 어떤 형식으로 검증할 수 있는가.
  • 보안팀: 실행 코드가 외부 연결 없이 통제된 환경에서만 돌 수 있는가.
  • 플랫폼팀: 영상 생성 비용과 지연시간이 교육용 기준에 맞는가.
  • 리스크관리: 코드 규칙이 잘못되면 잘못된 세계를 일관되게 만들 위험은 없는가.

현재 공개 내용에는 비용, 지연시간, 범용 벤치마크가 없다. 따라서 도입 판단보다 연구 관찰 대상으로 보는 편이 안전하다.

주요 용어

World model(세계모델): 행동과 사건에 따라 환경이 어떻게 바뀌는지 예측하는 모델 Persistent state(지속 상태): 이전 사건의 결과가 다음 장면에도 계속 남는 상태 정보 Proxy representation(프록시 표현): 최종 영상 대신 제약 조건을 담아두는 중간 표현 Spatiotemporal constraint(시공간 제약): 물체 위치와 시간 흐름에 따른 변화 규칙 Fine-tuning(미세조정): 특정 데이터에 맞게 기존 모델을 추가 학습하는 과정
